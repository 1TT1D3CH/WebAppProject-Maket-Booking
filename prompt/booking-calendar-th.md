# Prompt: หน้าจองของลูกค้า เลือกวันแบบปฏิทิน + จองล่วงหน้าได้ 365 วัน

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)
ต่อยอดจาก `missing-systems-th.md` ส่วน 2 (จองตามวัน/รอบ) และ `gap-fixes-th.md` (ตั้งค่าตลาด) ไม่ได้ใช้แทน

## 2 เรื่องที่จะแก้

1. **ตัวเลือกวันในหน้าจองของลูกค้า เปลี่ยนเป็นปฏิทินรายเดือน**
   ตอนนี้เป็นแถบ/ปุ่มวันเรียงกันให้เลือกได้แค่ไม่กี่วัน ให้เปลี่ยนเป็นปฏิทินที่เห็นทั้งเดือน
   เลื่อนเดือนก่อน/ถัดไปได้ วันที่จองไม่ได้เป็นสีเทาพร้อมบอกเหตุผล
2. **ขยายช่วงจองจาก 7 วันเป็น 365 วัน**
   ลูกค้าเลือกวันที่จะจองได้ตั้งแต่วันนี้ไปจนถึง 365 วันข้างหน้า (ปรับตัวเลขได้ในหน้าตั้งค่าตลาด)

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo แล้ววาง prompt ด้านล่างทั้งก้อน
2. agent จะสำรวจโค้ดก่อน แล้ว**หยุดให้ดูแผน** โดยเฉพาะว่า "7 วัน" ที่เห็นอยู่ตอนนี้มาจากตรงไหน
   (ช่วงจองล่วงหน้า หรือ จำนวนวันสูงสุดต่อ 1 การจอง หรือทั้งสองอย่าง) ตอบ agent ตามที่ต้องการ
3. agent commit ให้ แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง
   ถ้าแก้ `firestore.rules` ต้อง deploy rules พร้อมโค้ด (agent จะบอกคำสั่ง)

ค่าเริ่มต้นที่ prompt นี้เลือกไว้:
- **ช่วงจองล่วงหน้า = 365 วัน** (นับจากวันนี้ตามเวลาไทย วันนี้ = วันที่ 0)
- **จำนวนวันสูงสุดต่อ 1 การจอง** ไม่เปลี่ยนเอง ถ้าตอนนี้ถูกล็อกไว้ที่ 7 agent จะถามก่อนว่าจะขยายเป็นเท่าไร
  (ถ้าจะให้จองรวดเดียวได้หลายสิบหรือหลายร้อยวัน มีข้อจำกัดของ Firestore ที่ agent ต้องเช็กก่อน ดูข้อ C ใน prompt)

```

ข้อห้าม:
- ห้ามแก้โค้ดบันทึก/โหลดผัง (saveLayoutToFirestore, onSnapshot ของผัง, การรวมผังตั้งต้นกับข้อมูล Firebase)

========================================
ขั้น 0: สำรวจ แล้วหยุดรอผมตอบ
========================================
หาแล้วรายงานสั้น ๆ พร้อม file:line:
1) ตัวเลือกวันที่ลูกค้าเห็นตอนนี้อยู่ที่ไหน (แถบวันเหนือผัง, ใน BookingModal, หรือที่อื่น) หน้าตาเป็นแบบไหน
   และค่าที่เลือกเก็บที่ไหน (query ?date= / store / local state)
2) "7 วัน" มาจากตรงไหนบ้าง ไล่ให้ครบทุกจุด ทั้งโค้ดหน้าเว็บ, utils (date.js / marketCalendar.js),
   ค่าตั้งค่าตลาด (maxAdvanceDays, maxDaysPerBooking, maxSlotsPerBooking หรือชื่ออื่น) และ firestore.rules
   แยกให้ชัดว่าแต่ละจุดคือ
   ก. ช่วงจองล่วงหน้า (เลือกวันได้ไกลสุดกี่วัน)
   ข. จำนวนวัน/slot สูงสุดต่อ 1 การจอง
   ค. แค่จำนวนปุ่มวันที่แสดงในแถบ (ไม่ใช่ข้อจำกัดจริง)

5) มี settings ของตลาดใน Firestore ไหม doc ไหน ฟิลด์อะไร มีหน้าตั้งค่าตลาดให้ admin หรือยัง
6) มี useBreakpoint() / bottom sheet component ใช้ซ้ำได้ไหม

แล้วเสนอแผนตามด้านล่าง และถามผม 1 ข้อ:
"ตอนนี้จำนวนวันสูงสุดต่อ 1 การจองคือ X จะคงไว้ หรือเปลี่ยนเป็นเท่าไร"

========================================
A: ขยายช่วงจองเป็น 365 วัน
========================================
- ตั้งค่าคงที่กลางที่เดียว เช่น src/constants/booking.js: DEFAULT_MAX_ADVANCE_DAYS = 365
  ทุกจุดที่เจอในข้อ 2ก ให้อ่านจาก settings.maxAdvanceDays ?? DEFAULT_MAX_ADVANCE_DAYS ห้ามมีเลข 7 / 30 ฝังเหลือ
- ข้อ 2ค (จำนวนปุ่มในแถบ) ไม่ใช่ข้อจำกัด จะหายไปเองเมื่อเปลี่ยนเป็นปฏิทิน
- หน้าตั้งค่าตลาด (admin): ช่อง "จองล่วงหน้าได้สูงสุด (วัน)" ค่า 1..365 ค่าเริ่มต้น 365
  ถ้า doc settings มีค่าเก่า (เช่น 7 หรือ 30) อยู่แล้ว ไม่ต้องแก้ข้อมูลอัตโนมัติ แต่บอกผมว่าต้องเข้าไปเปลี่ยนในหน้าตั้งค่า
  หรือเขียน migration สั้น ๆ ที่ผมกดเองได้ (เสนอในขั้น 0)
- เหตุผลภาษาไทยเปลี่ยนตามค่าจริง: "จองล่วงหน้าได้ไม่เกิน 365 วัน"
- นับวันตามเวลาไทย (Asia/Bangkok) เสมอ วันสุดท้ายที่จองได้ = addDays(todayBangkok(), maxAdvanceDays)
  และยังต้องผ่านเงื่อนไขเดิมทั้งหมด (วันเปิดตลาด, วันหยุดพิเศษ, เวลาปิดรับจอง, รอบ)
- firestore.rules: ถ้า rules ตรวจช่วงวันอยู่ (เช่น ตรวจ date <= วันนี้+7) ปรับให้เป็น 365
  (rules อ่าน settings ด้วย get() ได้ถ้ามีอยู่แล้ว ไม่งั้นใช้ค่าคงที่ 365) ถ้า rules ไม่ได้ตรวจ ไม่ต้องเพิ่มใหม่

========================================
B: ปฏิทินเลือกวัน (component ใหม่ใช้ซ้ำได้)
========================================
สร้าง src/components/booking/BookingCalendar.vue (ชื่อตาม convention ของ repo)

props:
- modelValue: string (yyyy-mm-dd) ในโหมดเลือกวันเดียว หรือ string[] ในโหมดเลือกหลายวัน
- mode: 'single' | 'multiple'
- minDate, maxDate (yyyy-mm-dd) คำนวณจาก todayBangkok() และ maxAdvanceDays
- isDisabled(dateKey) => { disabled: boolean, reason?: string }  (ต่อกับ canBookDate/canBookSlot เดิม)
- dayStatus(dateKey) => 'free' | 'partial' | 'full' | 'taken' | null  (ไม่บังคับ ใช้แสดงจุด/สัญลักษณ์)
- maxSelect: number (โหมด multiple)
emit: update:modelValue, month-change({ year, month }) ให้ตัวแม่โหลดสถานะเฉพาะเดือนที่แสดง

หน้าตา/พฤติกรรม:
- หัว: ปุ่ม ‹ ›, ชื่อเดือน+ปี พ.ศ. ("ตุลาคม 2569"), ปุ่ม "วันนี้"
  แตะชื่อเดือนเปิดตัวเลือกเดือน/ปีแบบกริด 12 เดือน (เลื่อนไกล ๆ ได้เร็ว เพราะช่วงยาว 1 ปี)
  ปุ่ม ‹ ปิดเมื่อถึงเดือนของ minDate, ปุ่ม › ปิดเมื่อถึงเดือนของ maxDate
- หัวคอลัมน์ อา จ อ พ พฤ ศ ส (เริ่มวันอาทิตย์) ตารางสูงคงที่ 6 แถว กันหน้ากระโดดตอนเปลี่ยนเดือน
- สถานะวัน:
  วันนี้ = มีกรอบ, วันที่เลือก = พื้นสีหลัก ตัวขาว,
  จองไม่ได้ (ผ่านมาแล้ว / ตลาดปิด / เกินกำหนด / ปิดรับแล้ว) = ตัวเทาจาง ไม่ตอบสนองการแตะ
  แผงไม่ว่างวันนั้น (ใน BookingModal) = ขีดฆ่าหรือ ✕ สีแดงอ่อน
  dayStatus 'partial' / 'full' (บนผัง) = จุดเล็กใต้ตัวเลข สีเหลือง / แดง
- แตะ/hover วันที่จองไม่ได้: แสดงเหตุผล (tooltip บนคอม, ข้อความเล็กใต้ปฏิทินบนมือถือ เพราะ hover ไม่มี)
- โหมด multiple: แตะเพื่อเลือก/ยกเลิกทีละวัน ใต้ปฏิทินสรุป "เลือกแล้ว N วัน: 17, 18, 24 ต.ค." + ปุ่ม "ล้างทั้งหมด"
  เลือกเกิน maxSelect ไม่ได้ แสดง "เลือกได้สูงสุด N วันต่อการจอง"
  (ถ้า maxSelect มากกว่า 7) เพิ่มการเลือกเป็นช่วง: กด "เลือกเป็นช่วง" แล้วแตะวันแรกกับวันสุดท้าย
  ระบบใส่เฉพาะวันในช่วงที่จองได้และแผงว่าง แล้วบอกว่าข้ามไปกี่วันเพราะอะไร
- ขนาด: ช่องวันอย่างน้อย 40×40px (แตะง่ายบนมือถือ) ปฏิทินกว้างไม่เกิน ~360px บนคอม
  มือถือ (<640px) กว้างเต็ม bottom sheet / modal ใช้ dark mode ตามธีมที่มีอยู่
- เข้าถึงได้: role="grid", ปุ่มวันเป็น <button> มี aria-label "วันเสาร์ที่ 17 ตุลาคม 2569 จองไม่ได้: ตลาดไม่เปิดวันนี้",
  ลูกศรคีย์บอร์ดเลื่อนวัน, Enter/Space เลือก
- logic วันที่ทั้งหมดใช้ utils เดิม (todayBangkok, addDays, formatThaiDate ฯลฯ) ห้ามใช้ new Date('yyyy-mm-dd')
  ที่ตีความเป็น UTC แล้วเพี้ยนวัน

========================================
C: ใส่ปฏิทินในหน้าจองของลูกค้า
========================================
1) ตัวเลือกวันเหนือผัง (โหมด single):
   - แทนแถบวันเดิมด้วยปุ่มเล็ก "📅 ส. 17 ต.ค. 2569 ▾" + ปุ่ม ‹ › เลื่อนไปวันเปิดตลาดก่อน/ถัดไป
     แตะปุ่มวันเปิดปฏิทิน: คอม = popover ใต้ปุ่ม, มือถือ = bottom sheet
   - ถ้ามีรอบตลาด ปุ่มเลือกรอบยังอยู่ต่อจากวันเหมือนเดิม
   - ค่าที่เลือกยังเก็บใน query (?date=...&round=...) เหมือนเดิม ถ้า ?date= เกินช่วงหรือจองไม่ได้
     ให้เด้งไปวันเปิดถัดไปที่จองได้
   - dayStatus บนผัง (ไม่บังคับ แต่อยากได้): นับ lock ของเดือนที่แสดงเทียบจำนวนแผงทั้งหมด
     query เฉพาะช่วงเดือนที่แสดง (slotKey >= ต้นเดือน && < ต้นเดือนถัดไป) ตอน month-change
     ห้ามโหลด lock ทั้ง 365 วันทีเดียว ถ้า query แบบนี้ต้องใช้ index ใหม่ ให้เพิ่มใน firestore.indexes.json
     ถ้าทำแล้วอ่านเยอะเกินไป (เกิน ~1 query ต่อการเปลี่ยนเดือน) ให้ตัด dayStatus ออกแล้วบอกผม
2) ใน BookingModal (โหมด multiple):
   - แทนรายการวันเดิมด้วยปฏิทิน วันที่ที่เลือกบนผังถูกติ๊กไว้แล้ว
   - วันที่แผงนี้ไม่ว่าง: อ่าน lock ของแผงนี้เฉพาะเดือนที่แสดง (where stallId == X and slotKey ในช่วงเดือน)
     โหลดใหม่ตอนเปลี่ยนเดือน
   - ยอดรวม = ราคา × จำนวนวัน (× รอบ) อัปเดตทันที
   - ถ้ามีรอบ: หลังเลือกวัน ให้เลือกรอบต่อวันแบบเดิม (ไม่ต้องรื้อ ถ้าเดิมเป็นแบบไหนคงไว้)
3) ข้อจำกัดของ Firestore ที่ต้องเช็ก ถ้าผมตอบให้ขยายจำนวนวันต่อการจอง (ข้อ 2ข):
   - writeBatch/transaction ได้ไม่เกิน 500 การเขียน (booking + lock ทุก slot + audit log + อื่น ๆ)
   - rules ของคำขอหลายเอกสารเรียก get()/exists()/getAfter() ได้ไม่เกิน 20 เอกสารที่ไม่ซ้ำกันต่อคำขอ
     ถ้า rules ของ bookingLocks create เรียก exists()/get() ต่อ lock แต่ละตัว จองหลายวันจะชนเพดานนี้
     ให้ตรวจ rules จริง ถ้าชน เสนอทางแก้ (เช่น ใช้ resource == null แทน exists หรือแบ่งเป็นหลายการจอง)
     หยุดถามผมก่อนเปลี่ยนโครง rules
   - list ใน booking (dates/slots) ใหญ่ขึ้น ตรวจว่า rules ที่วนเช็ก list (เช่น hasAll / size) ยังใช้ได้
   - ใส่ตัวเลขสูงสุดที่ทำได้จริงในหน้าตั้งค่า (เช่น maxSlotsPerBooking สูงสุด = ค่าที่ทดสอบผ่าน)
```
