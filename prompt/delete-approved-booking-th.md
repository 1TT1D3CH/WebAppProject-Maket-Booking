# Prompt: ปุ่มลบการจองที่ตัดสินแล้ว (ยืนยัน 2 ขั้น) ในหน้าตรวจสลิปโอนเงิน

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)

## เป้าหมาย

ในหน้า **ตรวจสลิปโอนเงิน > แท็บ "ตัดสินแล้ว"** เมื่อเปิดรายละเอียดการจองที่อนุมัติแล้ว (หรือปฏิเสธ/ยกเลิก/หมดเวลาแล้ว)
มีปุ่ม **"ลบการจองนี้ถาวร"** แยกจากปุ่ม "ยกเลิกการจองนี้ (ผู้ดูแล)" ที่มีอยู่ ใช้ลบรายการทดสอบหรือรายการที่ซ้ำ
**ลบทั้งรายการออกจากฐานข้อมูล ไม่ใช่แค่รูปสลิป** หลังลบ รายการจะไม่อยู่ในหน้าตรวจสลิป, ประวัติการจองของผู้เช่า,
รายงานรายได้, ใบเสร็จ และผังอีกเลย (ไม่ใช่การซ่อนหรือเปลี่ยนสถานะเป็น "ลบแล้ว")
กดแล้วต้องยืนยัน 2 ขั้นก่อนลบจริง

## เรื่องที่เลือกไว้ให้แล้ว (บอก agent ได้ถ้าอยากเปลี่ยน)

- **ใครลบได้**: admin และ owner เท่านั้น ถ้าการจองนั้นออกเลขใบเสร็จแล้ว ลบได้เฉพาะ owner
  (เพราะเลขใบเสร็จจะขาดช่วงและรายงานรายได้จะเปลี่ยน)
- **ยืนยัน 2 ขั้น**
  1. หน้าต่างแรกแสดงสรุปว่าจะลบอะไร (แผง, ผู้เช่า, ยอดเงิน, วันที่) และผลที่ตามมา ต้องใส่เหตุผลการลบ แล้วกด "ถัดไป"
  2. หน้าต่างที่สองให้ **พิมพ์รหัสแผง** (เช่น `S-01`) ให้ตรง ปุ่ม "ลบถาวร" จึงกดได้
     และปุ่มจะกดได้หลังเปิดหน้าต่างนี้แล้ว 3 วินาที (กันกดรัว)
- **ลบแล้วเกิดอะไร** (ทำใน batch เดียว ถ้าส่วนไหนล้ม ไม่มีอะไรถูกลบเลย):
  ลบเอกสาร booking ทั้งเอกสาร (ชื่อ, เบอร์โทร, สินค้า, ยอดเงิน, วันที่ ทุกฟิลด์), ลบรูปสลิป,
  ลบข้อมูลคืนเงิน/บัญชีคืนเงิน/สลิปคืนเงิน, ลบ notification และสำเนาบนผังที่ชี้การจองนี้ (ถ้ามี), ปล่อยแผงให้ว่าง
  (เฉพาะถ้าแผง/lock ยังชี้มาที่การจองนี้) และเขียน audit log สั้น ๆ แค่ว่าใครลบ เมื่อไร เหตุผล รหัสแผง และยอดเงิน
  (ไม่เก็บชื่อ เบอร์โทร หรือข้อมูลอื่นของผู้เช่า เพราะ rules บังคับให้ทุกการเปลี่ยนต้องมี log และ log ลบไม่ได้)
- **rules บังคับด้วย** ไม่ใช่แค่ซ่อนปุ่ม ผู้เช่าหรือ admin ที่ไม่มี audit log ลบไม่ได้
- **ไม่แจ้งผู้เช่า** (ไม่ส่ง LINE / notification) เพราะส่วนใหญ่เป็นการลบรายการทดสอบหรือซ้ำ
  ถ้าต้องการให้ผู้เช่ารู้ ให้ใช้ปุ่ม "ยกเลิกการจองนี้" แทน
- รายการที่ **ลบไม่ได้**: pending / needs_slip / awaiting_slip / cancel_requested / การจองที่ยังรอคืนเงิน
  (refund.status == 'pending') ต้องตัดสินหรือคืนเงินให้เสร็จก่อน

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo วาง prompt ด้านล่างทีละส่วน
2. ส่วน 0 agent จะสำรวจโค้ดจริงแล้วหยุดถามคุณก่อน
3. agent commit ให้ แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง ส่วน 2 เตรียมคำสั่ง deploy ไว้ให้

| ส่วน | เรื่อง | หยุดถามก่อนไหม |
|---|---|---|
| 0 | สำรวจโค้ดจริง + เทียบ rules + เสนอแผน | **ใช่** |
| 1 | service ลบ + rules + หน้าต่างยืนยัน 2 ขั้น | ไม่ |
| 2 | ทดสอบรวม + เตรียม deploy rules กับโค้ดพร้อมกัน | ไม่ (แต่ไม่ deploy เอง) |

## ส่วนหัว (วางก่อนทุกส่วน)

```
คุณคือนักพัฒนา Vue 3 + Pinia + Vite + Tailwind + Firebase (Firestore, Auth, Hosting) ที่ทำงานใน repo
"Dynamic Market Stall Booking System" (ระบบจองแผงตลาด)

งานนี้: เพิ่มปุ่ม "ลบการจองนี้ถาวร" ในหน้าตรวจสลิปโอนเงิน แท็บ "ตัดสินแล้ว" (แผงรายละเอียดด้านขวา
ที่มีปุ่ม "ยกเลิกการจองนี้ (ผู้ดูแล)", "เปิดใบเสร็จ" และ "ประวัติการเปลี่ยนแปลง") ต้องยืนยัน 2 ขั้นก่อนลบ

สภาพโค้ด:
- มีแล้ว (อย่างน้อยตามที่ผมรู้): ตรวจสลิป (pending / needs_slip / approved / rejected / cancelled),
  audit log (auditLogs + lastAuditId), ยกเลิกโดยผู้ดูแล, ใบเสร็จ, การจองแบบเดิม (ไม่ระบุวัน)
  และอาจมีจองตามวัน (bookingLocks), คืนเงิน (refund, refundAccounts, refundSlips)
- prompt เก่า (slip-verification-th.md, missing-systems-th.md) ออกแบบโครงข้อมูลไว้ แต่โค้ดจริงอาจไม่ตรง
  ห้ามเดาว่ามีอะไรอยู่ ดูโค้ดจริงและ git log เสมอ ถ้าต่างจาก prompt ให้ยึดโค้ดจริงและบอกในสรุป
- Firebase Spark plan (ฟรี): ห้ามใช้ Cloud Functions, Cloud Storage, Extensions
  ทุกอย่างต้องทำได้จาก client + firestore.rules
- สิทธิ์: users/{uid}.role ใน rules มี isAdmin() = role in ['admin','owner'] และ isOwner() (ยืนยันจากไฟล์จริง)

บทเรียนวันที่ 10 ต.ค. (สำคัญ):
rules ที่ deploy ไม่ตรงกับโค้ดที่ deploy ทำให้ใช้งานไม่ได้ (Missing or insufficient permissions)
rules ใน repo อาจไม่ตรงกับที่ใช้จริงใน Console ต้องเทียบก่อนแก้ และ rules ใหม่ต้อง deploy พร้อมโค้ดในคำสั่งเดียว

กติกา:
1. ทำเฉพาะงานนี้ ห้าม refactor สิ่งที่ไม่เกี่ยว ห้ามแตะโค้ดบันทึก/โหลดผัง (saveLayoutToFirestore,
   onSnapshot ของผัง, stallSync) ถ้าจำเป็นต้องแตะ ให้หยุดอธิบายและถามผมก่อน
2. logic ลบอยู่ใน service/store เดียวกับการจองที่มีอยู่ (เช่น bookingService) ห้ามเขียน Firestore ใน component
3. การลบทุกอย่าง (booking, สลิป, ข้อมูลคืนเงิน, การปล่อยแผง, audit log) อยู่ใน writeBatch/transaction เดียว
   ถ้าส่วนไหนล้มต้องไม่มีอะไรถูกลบครึ่งทาง
4. UI ภาษาไทย รองรับ dark mode, ปุ่มบนมือถือ/iPad สูง >= 44px, input font >= 16px,
   ใช้ BaseModal/component เดิมถ้ามี ใช้สีแดงแบบเดียวกับปุ่ม "ยกเลิกการจองนี้" แต่ต้องดูต่างกันชัด
5. ห้ามกลืน error เงียบ ให้ log และแสดงข้อความไทย แยก permission-denied ออกจากเน็ตหลุด
6. ห้ามเพิ่ม dependency ใหม่
7. ก่อนทุก commit รัน npm run build และ npm run test:unit ต้องผ่าน
   แก้ firestore.rules ต้องเพิ่ม test ของ rules และรัน npm run test:rules (หรือ emulator ที่ repo ใช้)
   ถ้ารันไม่ได้ให้บอกตรง ๆ ว่ายังไม่ได้รัน ห้ามบอกว่าผ่าน
8. commit ขึ้นต้น "feat(booking-delete): ..." / "test(booking-delete): ..."
9. ห้าม git push, ห้าม firebase deploy ทุกรูปแบบ, ห้ามลบข้อมูลใน Firestore จริงเพื่อทดสอบ
   (ทดสอบใน emulator เท่านั้น) จนกว่าผมสั่งเองในแชท
10. จบแต่ละส่วนสรุปเป็นตาราง: ข้อ | สถานะ | ไฟล์ที่แก้ | วิธีทดสอบ พร้อมผล build/test จริง
    และรายการสิ่งที่ผมต้องทำเอง
```

## ส่วน 1: service ลบ + rules + หน้าต่างยืนยัน 2 ขั้น

```
ส่วน 1: ทำตามแผนที่ผมตกลงในส่วน 0

service (ไฟล์เดียวกับการจองที่มีอยู่):
- canDeleteBooking(booking, userRole) คืน { ok, reasonText } + unit test
  ลบได้เมื่อ: status in ['approved','rejected','cancelled','expired'] (ตามชื่อสถานะจริงในโค้ด)
  และไม่ใช่ refund.status == 'pending' และ (ไม่มีเลขใบเสร็จ หรือ userRole == 'owner')
  การจองเก่าที่ไม่มี status แต่แสดงเป็น "ยืนยันแล้ว" ให้นับเป็น approved
- deleteBookingPermanently(bookingId, { reason, confirmStallCode }) ใน runTransaction:
  1. อ่าน booking ล่าสุดในทรานแซกชัน ตรวจ canDeleteBooking อีกครั้ง (กันกรณีสถานะเปลี่ยนระหว่างเปิดหน้าต่าง)
     และ confirmStallCode ตรงกับรหัสแผงของ booking (ไม่สนตัวพิมพ์เล็กใหญ่ ตัดช่องว่างหัวท้าย)
  2. อ่านแผง/lock ที่เกี่ยวข้อง ปล่อยเฉพาะที่ยังชี้มาที่ bookingId นี้ (ใช้วิธีเดียวกับปุ่มยกเลิกโดยผู้ดูแล)
  3. เขียน auditLogs/delete_{bookingId} (หรือวิธีที่ตกลงในส่วน 0):
     action 'booking.delete', targetType 'booking', targetId/bookingId, marketId, reason,
     before = { stallCode, amount, status, createdAt } เท่านั้น ห้ามเก็บชื่อ เบอร์โทร สินค้า รูป หรือข้อมูลส่วนตัวใด ๆ ของผู้เช่า
  4. ลบ bookings/{id} ทั้งเอกสาร (ห้ามใช้ soft delete / ฟิลด์ deleted / แค่ล้างรูป), bookingSlips/{id},
     refundAccounts/{id}, refundSlips/{id}, notifications ที่อ้าง bookingId นี้ และ public copy ของแผง
     ถ้ามีและชี้มาที่การจองนี้ (ลบ doc ที่ไม่มีอยู่ใน batch ไม่ error แต่ให้ตรวจกับ rules ว่าผ่าน)
  5. เพิ่ม 'booking.delete' พร้อมคำแปล "ลบการจองถาวร" ใน src/constants/auditActions.js
- error: permission-denied -> "คุณไม่มีสิทธิ์ลบการจองนี้", สถานะเปลี่ยนแล้ว -> "การจองนี้เปลี่ยนสถานะแล้ว
  กรุณาเปิดใหม่", เน็ตหลุด -> "เชื่อมต่อไม่ได้ ยังไม่ได้ลบ ลองใหม่อีกครั้ง"

firestore.rules:
- bookings delete: isAdmin()
  && resource.data.status in [สถานะที่ลบได้] (หรือไม่มี status = การจองเก่า)
  && !(resource.data.refund.status == 'pending') (เขียนให้ปลอดภัยเมื่อไม่มีฟิลด์ refund)
  && (ไม่มีเลขใบเสร็จ || isOwner())
  && existsAfter(auditLogs/delete_{bookingId}) และ getAfter ของ log นั้นมี action == 'booking.delete',
     actorUid == request.auth.uid, targetId == bookingId, at == request.time
- auditLogs create: เพิ่ม 'booking.delete' ในรายการ action ที่ admin ใช้ได้ (tenant ใช้ไม่ได้)
  ส่วนอื่นของ auditLogs คงเดิม (update/delete = false)
- bookingSlips / refundAccounts / refundSlips delete: isAdmin() && !existsAfter(bookings/{id})
  (คือลบได้พร้อมกับการลบ booking เท่านั้น ถ้า rules เดิมอนุญาตกว้างกว่านี้ อย่าทำให้ฟีเจอร์เดิมพัง บอกผมก่อนเปลี่ยน)
- การปล่อยแผง/lock: ใช้เงื่อนไขเดิมของการยกเลิก แต่เพิ่มกรณี booking ใน getAfter() ไม่มีแล้ว
  และ lock/แผงชี้มาที่ bookingId นั้น

UI (แผงรายละเอียดในแท็บ "ตัดสินแล้ว"):
- ส่วน "โซนอันตราย" ล่างสุด ใต้ปุ่ม "ยกเลิกการจองนี้ (ผู้ดูแล)" และ "ประวัติการเปลี่ยนแปลง"
  ปุ่มขอบแดงไม่ทึบ ไอคอนถังขยะ ข้อความ "ลบการจองนี้ถาวร"
- แสดงปุ่มเฉพาะเมื่อ canDeleteBooking ผ่าน ถ้าไม่ผ่านเพราะออกใบเสร็จแล้วและเป็น admin
  ให้แสดงข้อความเล็ก "ออกใบเสร็จแล้ว เจ้าของตลาดเท่านั้นที่ลบได้" แทนปุ่ม
```
