# Prompt: ออกแบบแถบเครื่องมือผัง (Canvas Toolbar) ใหม่

วิธีใช้: เปิด AI coding agent ที่ root ของ repo แอปจองแผง แล้ววางทั้งก้อนในกรอบโค้ดด้านล่าง
(ถ้าทำระยะ F2 ใน fix-prompts-th.md ไปแล้ว จะมี CanvasToolbar.vue อยู่แล้ว agent จะแก้ไฟล์นั้นแทน)

## ปัญหาที่เห็นจากภาพหน้าจอ

- ปุ่มแบ่งเป็น 2 แถวที่ไม่มีหลักการ และแถวล่างล้นจนต้องเลื่อนแนวนอน (มี scrollbar)
- dropdown 3 อัน (ทางเข้า/ออก, สิ่งอำนวยความสะดวก, โครงสร้างหลัก) ทำหน้าที่เดียวกันคือ "เพิ่มวัตถุ" แต่แยกกันกินที่
- ปุ่มไอคอนล้วน 5 ปุ่มทางขวาไม่มีชื่อ ผู้ใช้เดาไม่ออกว่าคืออะไร
- ปุ่มแต่ละแบบสูง สี และขอบไม่เท่ากัน (บางอันพื้นขาว บางอันพื้นมืด)
- ไอคอนลูกศร 4 ทิศ (pan) และขนาดตลาด 30×20ม. ลอยอยู่โดยไม่มีป้ายบอก

## แบบใหม่ (สรุป)

แถวเดียว สูง 48px ไม่มี scroll แนวนอน แบ่งเป็น 3 กลุ่มชัดเจน:

```
จอใหญ่ (≥1024px)
┌──────────────────────────────────────────────────────────────────────────────────────┐
│ [+ เพิ่มแผง] [▣ เพิ่มวัตถุ ▾] │ [✋ เลื่อนผัง] [− 100% +] [⤢ พอดีจอ] [# Snap 0.5ม. ▾] │ [⤡ 30×20ม.] [⋯] [︿] │
└──────────────────────────────────────────────────────────────────────────────────────┘
   กลุ่ม "สร้าง"                    กลุ่ม "มุมมอง"                                   กลุ่ม "ผัง"

เมนู "เพิ่มวัตถุ ▾" (เปิดแล้ว)
┌───────────────────────────┐
│ ค้นหา...                  │
│ ใช้ล่าสุด                  │
│   🚻 ห้องน้ำ  🎤 เวที       │
│ ทางเข้า/ออก                │
│   🚪 ทางเข้า   🚪 ทางออก     │
│ สิ่งอำนวยความสะดวก         │
│   🚻 ห้องน้ำ  🚰 อ่างล้างมือ  │
│   🎤 เวที/เครื่องเสียง  💳 จุดชำระเงิน │
│ โครงสร้างหลัก              │
│   ▢ เสา  ▢ ทางเดิน  ▢ กำแพง  │
└───────────────────────────┘

จอกลาง (640–1023px): ปุ่มเหลือแค่ไอคอน + tooltip, ส่วนที่ไม่พอที่ย้ายเข้า [⋯]

มือถือ (<640px): แถบย้ายไปติดขอบล่างจอ ปุ่มใหญ่ 44px
┌──────────────────────────────────────┐
│  [+ แผง]  [▣ วัตถุ]  [− 100% +]  [⋯]  │
└──────────────────────────────────────┘
"วัตถุ" และ "⋯" เปิดเป็น bottom sheet แทน dropdown
```

## Prompt (คัดลอกทั้งก้อน)

```
คุณคือนักพัฒนา Vue 3 + Tailwind CSS ที่ทำงานใน repo ของ "Dynamic Market Stall Booking System"

งาน: ออกแบบแถบเครื่องมือเหนือผังตลาด (canvas toolbar) ใหม่ให้ใช้ง่ายขึ้น
ตอนนี้อยู่ใน src/components/.../StallCanvas.vue (หรือ CanvasToolbar.vue ถ้าแยกไว้แล้ว) ค้นจากข้อความ
"เพิ่มแผง", "พับเก็บ", "Snap", "สิ่งอำนวยความสะดวก" เพื่อหาตำแหน่งจริง

ปัญหาปัจจุบัน:
- ปุ่มเรียง 2 แถวไม่มีหลักการ แถวล่างล้นจนเกิด scrollbar แนวนอน
- dropdown "ทางเข้า/ออก", "สิ่งอำนวยความสะดวก", "โครงสร้างหลัก" แยกกัน 3 อัน ทั้งที่ทำหน้าที่เดียวกัน
- มีปุ่มไอคอนล้วนหลายปุ่ม (เพิ่มวัตถุด่วน) ที่ไม่มีชื่อหรือ tooltip
- ปุ่มสูง/สี/ขอบไม่สม่ำเสมอ, ไอคอน pan และขนาดตลาด (เช่น 30×20ม.) ไม่มีป้ายบอก

ขั้นที่ 1: อ่านโค้ดก่อน
- ระบุทุกปุ่ม/เมนูใน toolbar ปัจจุบัน ว่าแต่ละอันเรียกฟังก์ชัน/state อะไร
  (รวมปุ่มไอคอนล้วนทางขวา ให้หาว่าแต่ละอันเพิ่มวัตถุชนิดไหน)
- แสดงรายการนี้ให้ผมดูในสรุป ห้ามตัดฟังก์ชันใดทิ้ง ทุกการกระทำเดิมต้องยังทำได้

ขั้นที่ 2: แยก component (ถ้ายังไม่ได้แยก)
- สร้าง src/components/canvas/CanvasToolbar.vue รับ props / emit events ไปที่ StallCanvas.vue
  ห้ามย้าย logic ของผังเข้ามาใน toolbar, toolbar แค่แสดงผลและ emit
- ถ้ามีเมนูซ้อน ให้แยก ToolbarButton.vue, ToolbarMenu.vue, AddObjectMenu.vue

ขั้นที่ 3: จัด layout ใหม่เป็นแถวเดียว ไม่มี scroll แนวนอน
- 3 กลุ่ม คั่นด้วยเส้นแบ่งบาง ๆ:
  1) สร้าง: ปุ่มหลัก "+ เพิ่มแผง" (สีหลักของแอป ปุ่มเดียวที่เด่น) และปุ่ม "เพิ่มวัตถุ ▾"
  2) มุมมอง: โหมดเลื่อนผัง (toggle, แสดงสถานะ active), ซูม [− 100% +] (คลิกตัวเลขเพื่อรีเซ็ต 100%),
     "พอดีจอ" (แทน 1:1 ถ้า 1:1 คือรีเซ็ตซูม ให้รวมไว้ที่คลิกตัวเลข), "Snap 0.5ม. ▾" (toggle + เลือกขนาด)
  3) ผัง (ชิดขวา): ขนาดตลาด "30×20ม." เป็นปุ่มที่คลิกแล้วเปิดตั้งค่าขนาด (ถ้าเดิมแก้ได้),
     ปุ่ม "⋯ เพิ่มเติม", ปุ่ม "พับเก็บ" (ไอคอน ︿ พร้อม tooltip)
- ทุกปุ่มสูงเท่ากัน 32px (มือถือ 44px), มุมโค้ง สีพื้น ขอบ แบบเดียวกัน
  มีแค่ 2 สไตล์: primary (เพิ่มแผง) และ ghost (อื่น ๆ), สถานะ active ใช้พื้นสีอ่อนของสีหลัก
- ห้ามใช้ overflow-x-auto บน toolbar

ขั้นที่ 4: รวม dropdown 3 อัน + ปุ่มไอคอนด่วน เป็นเมนู "เพิ่มวัตถุ" อันเดียว
- เมนูมีหัวข้อแบ่งหมวด: ทางเข้า/ออก, สิ่งอำนวยความสะดวก, โครงสร้างหลัก
  แต่ละรายการมีไอคอน + ชื่อภาษาไทยเสมอ
- ด้านบนมีหมวด "ใช้ล่าสุด" (สูงสุด 4 รายการ เก็บใน localStorage ครอบ try/catch)
  แทนที่ปุ่มไอคอนล้วนเดิม
- ถ้ารายการรวมเกิน ~10 ให้มีช่องค้นหาด้านบน
- เมนูใช้ <Teleport to="body"> และคำนวณตำแหน่งจากปุ่ม เพื่อไม่ถูกตัดโดย container
- ใช้แป้นลูกศรขึ้นลงเลือก, Enter เพิ่ม, Esc ปิด, คลิกนอกเมนูปิด

ขั้นที่ 5: รองรับจอแคบ (ไม่ให้ล้น)
- ใช้ ResizeObserver วัดความกว้าง toolbar แล้วซ่อนป้ายข้อความก่อน (เหลือไอคอน + tooltip)
  ถ้ายังไม่พอ ให้ย้ายรายการเข้าเมนู "⋯" ตามลำดับความสำคัญ (ซ่อนก่อน -> ซ่อนหลัง):
  ขนาดตลาด, พอดีจอ, Snap, โหมดเลื่อนผัง, ซูม
  "+ เพิ่มแผง", "เพิ่มวัตถุ", "⋯" ต้องเห็นเสมอ
- จอ <640px: toolbar ย้ายไป fixed ขอบล่างจอ (มี padding env(safe-area-inset-bottom))
  เหลือ [+ แผง] [วัตถุ] [− % +] [⋯] และเมนูเปิดเป็น bottom sheet
  ผังต้องเว้นที่ด้านล่างไม่ให้ toolbar ทับ (สอดคล้องกับข้อ G6 ใน code review)

ขั้นที่ 6: ใช้งานง่ายและเข้าถึงได้
- ทุกปุ่มไอคอนมี aria-label และ tooltip ภาษาไทย (แสดงทั้ง hover และ focus, หน่วง ~400ms)
  tooltip บอกคีย์ลัดด้วย เช่น "ซูมเข้า (+)"
- คีย์ลัด (ทำงานเฉพาะเมื่อ focus ไม่ได้อยู่ใน input): N เพิ่มแผง, O เปิดเมนูวัตถุ,
  + / − ซูม, 0 รีเซ็ตซูม, Shift+1 พอดีจอ, G สลับ Snap, กด Space ค้างเพื่อเลื่อนผัง
- toolbar มี role="toolbar" และ aria-label="เครื่องมือผัง"
- รองรับ dark mode ทุกส่วน ตัวอักษรและพื้นต้องมี contrast อ่านออก

ข้อห้าม:
- ห้ามเปลี่ยนพฤติกรรมของผัง (การลาก, การบันทึก, รูปแบบข้อมูล) ทำเฉพาะ UI ของ toolbar
- ห้ามเพิ่ม dependency ใหม่ ถ้าจำเป็นจริงให้ถามผมก่อน
- commit ย่อยตามขั้น ข้อความ commit ขึ้นต้น "feat(toolbar): ..."
- หลังแต่ละ commit รัน npm run build ต้องผ่าน (และ lint/test ถ้ามี)

เมื่อเสร็จ สรุปให้ผม:
1. ตารางเทียบ: การกระทำเดิม | อยู่ตรงไหนใน toolbar ใหม่
2. ไฟล์ที่สร้าง/แก้
3. วิธีทดสอบด้วยมือ: จอกว้าง 1440px, 900px, 375px (DevTools) ทั้ง light/dark,
   ใช้คีย์บอร์ดอย่างเดียวได้ครบ, ไม่มี scrollbar แนวนอนที่ความกว้างใดเลย
```
