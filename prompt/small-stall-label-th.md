# Prompt: แผงเล็กบนผังตลาด ข้อความล้นออกนอกแผง

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)

## ปัญหา

แผงที่ขนาดเล็ก (เช่น 2.5×2 ม. หรือซูมออก) ข้อความในแผงล้นออกนอกกรอบ:
- ชื่อโซน/ชื่อร้าน เช่น "โซนอาหาร &..." ทะลุออกนอกแผงไปทับพื้นที่ข้าง ๆ
- ป้ายสถานะ "จองแล้ว" ถูกบีบจนตัวอักษรเรียงแนวตั้งทีละตัว (จ / อ / ง / แล้ / ว) ห้อยลงใต้แผง

## แบบที่ตั้งเป้า

```
แผงใหญ่ (ที่พอ)          แผงกลาง               แผงเล็ก                 แผงเล็กมาก
┌──────────────┐      ┌──────────┐        ┌──────┐              ┌───┐
│ S-02    ฿500 │      │ S-02     │        │ S-02 │              │ ● │ ← จุดสีสถานะ
│ โซนอาหาร &…  │      │ ● จองแล้ว │        │  ●   │              └───┘
│ [จองแล้ว]     │      └──────────┘        └──────┘
└──────────────┘
ข้อความทุกอย่างอยู่ในกรอบแผงเสมอ ไม่ล้น ไม่ตัดคำแนวตั้ง
ข้อมูลที่ซ่อนไป ดูได้จาก tooltip ตอน hover / แตะ และจาก pop up รายละเอียดแผงเดิม
```

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo แล้ววาง prompt ด้านล่างทั้งก้อน
2. แนบภาพหน้าจอแผงที่ข้อความล้น (ภาพที่ส่งในเธรดนี้) ไปด้วย
3. agent จะสำรวจโค้ดที่วาดแผงแล้วหยุดให้ดูก่อนลงมือ commit ให้ แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง

---

## Prompt (คัดลอกทั้งก้อน)

```
คุณคือนักพัฒนา Vue 3 + Pinia + Vite + Tailwind CSS ที่ทำงานใน repo "Dynamic Market Stall Booking System"

งาน: แก้การแสดงข้อความบนแผง (stall) ในผังตลาด ให้ไม่ล้นออกนอกกรอบแผงเมื่อแผงเล็ก
(แผงขนาดเล็กจริง เช่น 2.5×2 ม. หรือเมื่อซูมออกจนแผงเล็กบนจอ)

อาการที่เห็นจริง (ดูภาพที่แนบ):
- ชื่อโซน/ชื่อร้าน "โซนอาหาร &..." ล้นออกนอกแผง ไปอยู่ใต้/ข้างแผง
- ป้าย "จองแล้ว" ถูกบีบจนตัวอักษรเรียงแนวตั้งทีละตัว ห้อยลงนอกแผง
- กล่องที่มี "S-02  ฿500  2.5×2 ม." อาจเป็น tooltip/การ์ด hover ให้ตรวจว่าเป็นส่วนไหนของ UI

สำคัญ: ผมไม่รู้ว่าแผงวาดด้วยอะไร (div + CSS absolute, SVG <rect>/<text>, canvas, Konva/vue-konva ฯลฯ)
ห้ามเดา ให้สำรวจโค้ดจริงก่อน

กติกา:
1. งาน UI การแสดงผลเท่านั้น ห้ามแก้โครงข้อมูล Firestore, firestore.rules, firebase.json, .env,
   และโค้ดบันทึก/โหลดผังหรือการจอง (saveLayoutToFirestore, onSnapshot, stallSync, action ใน store ที่อ่าน/เขียน
   Firestore) ถ้าจำเป็นต้องแก้ให้หยุดถามผมก่อน
2. ห้ามเปลี่ยนขนาด/ตำแหน่งจริงของแผงในผัง ห้ามเปลี่ยนสีสถานะเดิม ห้ามเปลี่ยนการคลิกเลือก/ลาก/จอง
3. ห้ามเพิ่ม dependency ใหม่ (ถามก่อนถ้าจำเป็นจริง)
4. ข้อความไทย รองรับ dark mode และต้องใช้ได้ทั้งหน้าผู้เช่า (ดูผัง/จอง) และหน้า Admin Builder
5. ก่อนทุก commit รัน npm run build ต้องผ่าน และ lint / test:unit ถ้ามี ถ้ารันไม่ได้ให้บอกตรง ๆ
6. commit ย่อย ข้อความขึ้นต้น "fix(stall-label): ..."
7. ห้าม git push, ห้าม firebase deploy, ห้าม force push จนกว่าผมสั่ง

ขั้นที่ 1: สำรวจ (ยังไม่แก้) แล้วหยุดรอผม
- git status / git log -3 --oneline (ถ้ามีไฟล์แก้ค้างที่ไม่ใช่ของงานนี้ ห้ามแตะ ให้บอกผม)
- หา component ที่วาดแผงบนผัง: ค้น "จองแล้ว", "ว่าง", "status", "stall", "Stall", "booked",
  "zoneName", "zone", "<rect", "<text", "foreignObject", "v-stage", "v-rect", "v-text", "canvas",
  "scale", "zoom", "transform"
- หาที่มาของกล่อง hover/tooltip ในภาพ (ข้อความ "฿" และ "ม.")
- อธิบายให้ผม:
  a) แผงวาดด้วยเทคนิคอะไร ไฟล์ไหน บรรทัดไหน
  b) ขนาดแผงบนจอคำนวณจากอะไร (เมตร × px ต่อเมตร × zoom ?) และรู้ขนาดเป็น px ตอน render ได้ไหม
  c) ข้อความแต่ละบรรทัดในแผงมีอะไรบ้าง (รหัสแผง, ชื่อโซน/ร้าน, ราคา, ขนาด, ป้ายสถานะ) และวางยังไง
  d) สาเหตุที่ข้อความล้น (ไม่มี overflow:hidden, ไม่มี truncate, ป้ายสถานะ width แคบแต่ไม่มี
     white-space:nowrap, ใช้ word-break:break-all, ข้อความ SVG ไม่ถูกตัด ฯลฯ)
- เสนอแผนตามขั้นที่ 2 ให้เหมาะกับเทคนิคที่ใช้จริง แล้วหยุดรอผมตอบ

ขั้นที่ 2: แสดงข้อความตามขนาดแผง (responsive ตามขนาดแผงบนจอ ไม่ใช่ตามขนาดหน้าจอ)
- คำนวณขนาดแผงบนจอเป็น px (กว้าง w, สูง h หลังคูณ zoom) แล้วเลือกระดับการแสดงผล เช่น
  - ใหญ่ (w ≥ ~120 และ h ≥ ~70): รหัสแผง + ชื่อโซน/ร้าน (ตัด …) + ป้ายสถานะ (+ ราคาถ้าเดิมมี)
  - กลาง (w ≥ ~70 และ h ≥ ~40): รหัสแผง + ป้ายสถานะแบบย่อ (จุดสี + "จองแล้ว" ถ้าพอ)
  - เล็ก (w ≥ ~36 และ h ≥ ~24): รหัสแผงอย่างเดียว + จุดสีสถานะ
  - เล็กมาก: จุดสีสถานะ หรือแค่สีพื้นของแผง ไม่มีข้อความ
  ตัวเลขข้างบนเป็นค่าเริ่มต้น ปรับได้ตามขนาดฟอนต์จริง ให้รวมเป็นค่าคงที่จุดเดียว
- ถ้าเป็น HTML/CSS: กรอบแผง overflow:hidden, ข้อความแต่ละบรรทัด truncate
  (white-space:nowrap; overflow:hidden; text-overflow:ellipsis; min-width:0), ป้ายสถานะ whitespace-nowrap
  ห้ามใช้ break-all/break-words กับป้ายสถานะ ใช้ container query (@container) หรือ ResizeObserver
  ได้ถ้าเหมาะกว่าการคำนวณเอง
- ถ้าเป็น SVG: ใช้ clipPath ตามกรอบแผง, ตัดข้อความเองให้ไม่เกินความกว้าง (วัดด้วย getComputedTextLength
  หรือประมาณจากจำนวนตัวอักษร) แล้วเติม "…", ห้ามให้ <text> ขึ้นบรรทัดทีละตัว
- ถ้าเป็น canvas/Konva: ใช้ width + ellipsis + wrap:'none' ของ Text (หรือ clip ของ Group)
  และซ่อน node ที่ไม่พอที่แสดง
- ขนาดฟอนต์: ย่อลงได้ตามขนาดแผงแต่ไม่ต่ำกว่า ~10px บนจอ ถ้าต่ำกว่านั้นให้ลดระดับแทนการย่อต่อ
- ข้อความที่ถูกซ่อน/ตัดต้องยังหาดูได้: title / aria-label ของแผงมีข้อความเต็ม
  (รหัส ชื่อโซน สถานะ ราคา ขนาด) และ tooltip/การ์ด hover กับ pop up รายละเอียดแผงเดิมยังทำงานเหมือนเดิม
- บนมือถือ/iPad ที่ไม่มี hover: แตะแผงแล้วเห็นข้อมูลเต็มตามที่แอปทำอยู่แล้ว ห้ามทำให้การแตะเลือก/จองเปลี่ยน
- tooltip/การ์ด hover: ต้องไม่ล้นขอบจอ และไม่บังตัวแผงที่กำลังชี้ (ถ้าเดิมบังให้ขยับไปด้านที่มีที่ว่าง)
- เมื่อซูมเข้า/ออก หรือหมุนจอ ระดับการแสดงผลต้องเปลี่ยนตามทันที โดยไม่หน่วง (ถ้าคำนวณทุกแผงทุกเฟรม
  ให้ทำแบบเบา ไม่ใช้ ResizeObserver ต่อแผงถ้าแผงมีจำนวนมาก)
- แผงหมุน (rotation) ถ้ามี: ข้อความยังอ่านได้และอยู่ในกรอบ

ขั้นที่ 3: ตรวจ
- unit test ของฟังก์ชันเลือกระดับการแสดงผล (ขนาดต่าง ๆ ได้ระดับถูก) และฟังก์ชันตัดข้อความ (ถ้ามี)
- ถ้ามี Playwright หรือรันเบราว์เซอร์ headless ได้โดยไม่เพิ่ม dependency: เปิดผังที่มีแผงเล็ก
  ที่ zoom ต่ำสุด / ปกติ / สูงสุด บนจอ 375×667, 768×1024, 1440×900 แล้วตรวจว่า
  (a) กรอบของข้อความทุกอันอยู่ในกรอบแผงของมัน (b) ไม่มีป้ายสถานะที่สูงเกิน 1 บรรทัด
  ถ้าทำไม่ได้ให้บอกและให้รายการตรวจมือ
- ตรวจทั้ง light/dark mode และทั้งหน้าผู้เช่ากับหน้า Admin Builder

สรุปให้ผม:
1. สาเหตุที่ข้อความล้น (ไฟล์:บรรทัด)
2. ตารางระดับการแสดงผล: ระดับ | เงื่อนไขขนาด | แสดงอะไร
3. ไฟล์ที่แก้ และรายการ commit
4. ยืนยันด้วย git diff --stat ว่าไม่ได้แก้ firestore.rules และโค้ดบันทึก/โหลด
5. วิธีลองเอง: npm run dev -- --host แล้วเปิดผังที่มีแผงเล็ก ซูมเข้า/ออก บนคอมและมือถือ
6. คำสั่ง push / deploy ที่ผมต้องรันเอง (ยังไม่ต้องรัน)
```
