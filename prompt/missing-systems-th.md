# Prompt: 6 ระบบที่ยังขาด (หมดเวลาจอง, ยกเลิก/คืนเงิน, จองตามวัน/รอบ, รายงานรายได้, ประวัติ+ใบเสร็จ, Audit log)

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)

## เป้าหมาย

1. **หมดเวลาจองอัตโนมัติ** กดจองแล้วกันแผงไว้ 30 นาที ถ้าไม่ส่งสลิปในเวลา แผงกลับมาว่างเอง
2. **ยกเลิกและคืนเงิน** ผู้เช่าขอยกเลิกได้ admin/owner อนุมัติการยกเลิกและบันทึกว่าคืนเงินแล้ว
3. **จองตามวันหรือรอบตลาด** แผงเดียวกันให้คนละคนจองในคนละวัน (หรือคนละรอบในวันเดียวกัน) ได้
4. **รายงานรายได้ + ส่งออก Excel** owner ดูยอดรายวัน/รายเดือน และดาวน์โหลดเป็นไฟล์ .xlsx
5. **ประวัติการจองของลูกค้า + ใบเสร็จ PDF**
6. **Audit log** บันทึกว่าใครอนุมัติ/แก้ไขอะไร เมื่อไร แก้หรือลบย้อนหลังจากหน้าเว็บไม่ได้

ทั้งหมดต้องทำได้บน **Firebase Spark plan (ฟรี)** ไม่มี Cloud Functions

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo วาง **"ส่วนหัว"** ตามด้วย prompt ของส่วนนั้น **ทีละส่วน ตามลำดับ**
2. ส่วน 0 agent จะสำรวจโค้ดจริงก่อน แล้วบอกว่าระบบไหน **มีอยู่แล้ว / มีบางส่วน / ยังไม่มี**
   ส่วนที่มีครบแล้ว agent จะแค่ตรวจตาม checklist ของส่วนนั้นและทำเฉพาะที่ขาด ส่วนไหนไม่ต้องการก็ข้ามได้
3. agent commit ให้ทีละส่วน แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง ส่วน 7 เตรียมคำสั่ง deploy ไว้ให้

ลำดับส่วนไม่ตรงกับลำดับความสำคัญ เพราะบางระบบเป็นฐานของระบบอื่น:
audit log ต้องมีก่อนเพื่อให้ทุกการกระทำหลังจากนั้นบันทึกลงไปตั้งแต่แรก และการจองตามวันเปลี่ยนวิธีกันแผง
ถ้าทำหมดเวลาจองก่อนจะต้องรื้อทำใหม่

|---|---|---|---|

### เรื่องที่เลือกไว้ให้แล้ว (บอก agent ได้ถ้าอยากเปลี่ยน)

- **หมดเวลาจองทำแบบ "หมดอายุเอง" โดยไม่ต้องมี server**: การจองเก็บเวลาเริ่มกันแผงจากเวลา server
  (`request.time`) rules ถือว่าการกันแผงที่เกิน 30 นาทีแล้วเป็นแผงว่าง คนอื่นจองทับได้ทันที
  และส่งสลิปหลังหมดเวลาไม่ได้ ผังแสดงแผงนั้นเป็นว่างเมื่อถึงเวลา ไม่ต้องรอใครมากดล้าง
  สถานะ "หมดเวลา" ในรายการจองจะถูกตั้งโดยหน้าเว็บที่เปิดอยู่ (ผู้เช่าเอง หรือ admin)
- **เวลา**: กันแผงรอสลิป 30 นาที, ขอสลิปใหม่ให้เวลา 24 ชั่วโมง ตั้งค่าได้ในหน้าตั้งค่าตลาด
- **ยังแนบสลิปตอนกดจองได้เหมือนเดิม** (ตาม `slip-verification-th.md`) ถ้าแนบเลยก็ข้ามช่วง 30 นาทีไปเป็น "รอตรวจสลิป"
- **ยกเลิก**: ก่อนส่งสลิป/ระหว่างรอตรวจ ผู้เช่ายกเลิกเองได้ทันที; หลังอนุมัติแล้วเป็น "ขอยกเลิก" ให้ admin/owner อนุมัติ
  ระบบไม่โอนเงินเอง admin โอนคืนนอกระบบแล้วมาบันทึก (ยอด, วิธี, วันที่, รูปสลิปคืนเงินถ้ามี)
  ยอดคืนที่แนะนำคิดจากนโยบายในหน้าตั้งค่า (ค่าเริ่มต้น: ยกเลิกก่อนวันขาย 3 วันขึ้นไปคืนเต็ม, น้อยกว่านั้นคืน 50%,
  วันขายหรือหลังจากนั้นไม่คืน) admin แก้ยอดได้แต่ต้องใส่เหตุผล
- **รอบตลาด**: ถ้าไม่ได้ตั้งรอบ = วันละ 1 รอบ (เหมือนจองตามวัน) ถ้าตั้ง เช่น เช้า/เย็น แผงเดียวกันจองแยกรอบได้
- **Audit log**: หน้าเว็บเขียน log ใน batch เดียวกับการกระทำ และ rules บังคับว่าต้องมี log ไม่งั้นการกระทำนั้นไม่ผ่าน
  log สร้างได้อย่างเดียว แก้/ลบไม่ได้ owner และ admin ดูได้ ผู้เช่าดูไม่ได้
  (owner ที่เข้า Firebase Console ยังลบได้ อันนี้กันไม่ได้บน Spark)
- **Excel**: ไฟล์ .xlsx จริง ใช้ library เล็กหนึ่งตัวที่โหลดเฉพาะตอนกดส่งออก agent จะเสนอชื่อและขนาดในส่วน 0 ให้คุณตกลงก่อน
- **ใบเสร็จ PDF**: หน้าใบเสร็จที่จัดหน้าสำหรับพิมพ์ แล้วกด "บันทึกเป็น PDF" จากเมนูพิมพ์ของเครื่อง
  (ไม่ต้องเพิ่ม library, ภาษาไทยแสดงถูกแน่นอน ใช้ได้บน iPhone/iPad/คอม) เลขใบเสร็จเรียงต่อกันตอนอนุมัติ
  เป็น "ใบเสร็จรับเงิน" ไม่ใช่ใบกำกับภาษี
- **รายงานรายได้**: owner ดูได้ (admin ไม่เห็นเมนูนี้) นับรายได้ตาม **วันขาย** ของแต่ละวัน/รอบที่จอง
  ยอดคืนเงินหักตามวันที่คืนจริง
- **แจ้งเตือน**: ใช้เฉพาะระบบแจ้งเตือนในแอปที่มีอยู่ (notificationStore) ส่งเหตุการณ์ใหม่ (หมดเวลา, อนุมัติยกเลิก, คืนเงินแล้ว)
  ไม่มีการแจ้งเตือนนอกแอปทุกชนิด

### ไม่แตะ (มีงานอื่นดูอยู่)

ห้ามแก้โค้ดบันทึก/โหลดผัง (`saveLayoutToFirestore`, onSnapshot/โหลดผัง, การรวมผังตั้งต้นกับข้อมูล Firebase)
ถ้าระบบไหนจำเป็นต้องแก้ตรงนั้น agent ต้องหยุดถามก่อน

```

"Dynamic Market Stall Booking System" (ระบบจองแผงตลาด)
```

## ส่วน 0: สำรวจโค้ดจริง + เทียบ rules + เสนอแผน

```

      ว่าง / ไม่มี = วันละรอบเดียว id 'all'
      slotKey = 'YYYY-MM-DD' + '_' + roundId เช่น '2026-10-17_all', '2026-10-17_morning'
   ข. bookings/{autoId} หนึ่งการจอง = หนึ่งแผง หลาย slot ได้
      { marketId, stallId, stallNo, zoneId, zoneName, tenantId, customerName, customerPhone, shopName,
        slots: ['2026-10-17_all', ...] (เรียง ไม่ซ้ำ 1..maxSlotsPerBooking), firstDate, lastDate,
        pricePerSlot, totalAmount, status, statusReason,
        holdStartedAt, holdMinutes, (หมดเวลาจอง: ส่วน 3)
        cancelRequest { reason, requestedAt }, refund { ... } (ส่วน 4)
        receiptNo (ส่วน 5), lastAuditId (ส่วน 1),
        createdAt, updatedAt, decidedBy, decidedAt }
      ฟิลด์ที่มีอยู่แล้วให้ใช้ชื่อเดิม อย่าเปลี่ยนชื่อ
   ค. bookingLocks/{marketId}_{stallId}_{slotKey} (กันจองซ้ำ ไม่มีข้อมูลส่วนตัว ผู้ใช้ที่ล็อกอินอ่านได้)
      { marketId, stallId, date, roundId, slotKey, bookingId, status, holdStartedAt, holdMinutes }
      ถ้าตอนนี้ใช้ stallHolds หรือ stall.status อยู่ ให้เสนอวิธีเปลี่ยนมาใช้ bookingLocks
      และบอกว่ากระทบโค้ดผังตรงไหน (ห้ามแก้โค้ดบันทึก/โหลดผัง ให้ผังอ่าน locks แยกเพื่อระบายสี)
   ง. สถานะการจอง (state machine เต็ม):
      awaiting_slip (กันแผงแล้ว รอส่งสลิปภายใน holdMinutes) -> pending (ส่งสลิปแล้ว)
                                                           -> expired (หมดเวลา, ปล่อยแผง)
                                                           -> cancelled (ผู้เช่ายกเลิกเอง)
      pending -> approved / needs_slip / rejected / cancelled (ผู้เช่ายกเลิกเอง)
      needs_slip (ให้เวลา resubmitHours) -> pending / expired / cancelled
      approved -> cancel_requested (ผู้เช่าขอยกเลิก) -> cancelled (admin อนุมัติ) / approved (admin ไม่อนุมัติ)
      approved -> cancelled (admin ยกเลิกเองพร้อมเหตุผล)
      cancelled ที่เคยจ่ายเงินแล้วมี refund.status: 'pending' (ต้องคืน) -> 'refunded' / 'none' (ไม่คืนตามนโยบาย)
      การจองเก่าที่ไม่มี status = ยืนยันแล้ว (legacy)
   จ. auditLogs/{autoId} (ส่วน 1)
   ฉ. counters/receipts { year, next } (ส่วน 5)

6) การจองเดิมที่ไม่มีวันที่: นับว่ามีกี่รายการที่ยังกันแผงอยู่ (อ่านอย่างเดียว ผ่าน emulator export
```

## ส่วน 3: หมดเวลาจองอัตโนมัติ

```

  ตั้ง timer หนึ่งตัวต่อหน้า ปลุกตอน lock ที่ใกล้หมดที่สุดหมดเวลา แล้ววาดสีใหม่ (ไม่ใช่ timer ต่อแผง)
- จองทับแผงที่เพิ่งหมดเวลาแล้วโดนปฏิเสธ (นาฬิกาเครื่องเร็วกว่า server) แสดง
  "แผงนี้ยังถูกกันอยู่อีกไม่กี่วินาที ลองใหม่อีกครั้ง" ไม่ใช่ error สิทธิ์

ตั้งสถานะ 'expired' (ให้ข้อมูลสะอาด แต่ความถูกต้องไม่ขึ้นกับขั้นนี้):
- หน้า "การจองของฉัน" ของผู้เช่า และหน้าจัดการการจองของ admin เมื่อเจอ awaiting_slip / needs_slip ที่หมดเวลาแล้ว
  ให้เขียน status 'expired' + ลบ lock ที่ยังชี้ booking นี้ + audit log action booking.expire
  actorRole ตามคนที่เปิดอยู่ ทำทีละไม่เกิน 20 รายการต่อครั้ง ถ้าชนกัน (อีกคนทำไปแล้ว) ข้ามเงียบได้
- การจองที่ถูกจองทับไปแล้วก็ต้องเปลี่ยนเป็น expired ได้ (lock ไม่ชี้ booking นี้แล้ว)

needs_slip (ขอสลิปใหม่):
- ตอน admin กดขอสลิปใหม่ ตั้ง holdStartedAt ใหม่ และ holdMinutes = resubmitHours * 60

- ผู้เช่าเห็นนับถอยหลัง "ส่งสลิปใหม่ภายใน 23 ชม. 12 นาที" หมดเวลาแล้วเหมือน awaiting_slip

แจ้งเตือน:
- ใช้ระบบแจ้งเตือนในแอปที่มีอยู่ ให้แจ้ง "การจองแผง A-01 หมดเวลาแล้ว" ตอนที่ตั้ง expired
- เตือนล่วงหน้า "เหลือ 10 นาที" ทำได้เฉพาะตอนผู้เช่าเปิดแอปอยู่ (แสดงในแอป)

ตั้งค่าตลาด: paymentHoldMinutes (10-120), resubmitHours (1-72)

firestore.rules:
- ฟังก์ชัน holdExpired(data) = data.status in ['awaiting_slip','needs_slip'] &&
  request.time > data.holdStartedAt + duration.value(data.holdMinutes, 'm')
- bookingLocks create/update: อนุญาตถ้ายังไม่มี lock หรือ lock เดิม holdExpired() (จองทับ)

- booking awaiting_slip -> pending: เจ้าของเท่านั้น, ยังไม่ holdExpired, lock ทุก slot ยังชี้ booking นี้
  (rules ตรวจได้ทีละ get จำกัด 10 get/existsAfter ต่อ request ถ้า slot เกินให้ลด maxSlotsPerBooking
  หรือเก็บ lock หลักตัวเดียว เสนอวิธีและบอกผม), bookingSlips สร้างได้เฉพาะตอนนี้
- booking -> expired: ผู้ใช้ที่ล็อกอินคนไหนก็ได้ แต่ต้อง holdExpired() หรือ lock ไม่ชี้ booking นี้แล้ว,
  แก้ได้เฉพาะ status, updatedAt, lastAuditId; ลบ lock ได้เฉพาะ lock ที่ชี้ booking นี้และหมดอายุ
- ผู้เช่าตั้ง holdStartedAt / holdMinutes เองไม่ได้นอกจากตอนสร้าง

Test rules (ใช้ withSecurityRulesDisabled ใส่ข้อมูลที่ holdStartedAt ย้อนหลังไป 31 นาที):
จองทับแผงที่หมดเวลาแล้วผ่าน, จองทับแผงที่ยังไม่หมดเวลาไม่ผ่าน, ส่งสลิปหลังหมดเวลาไม่ผ่าน,
```
