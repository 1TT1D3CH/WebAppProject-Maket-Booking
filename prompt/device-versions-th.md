# Prompt: แยกหน้าจอเป็นเวอร์ชันมือถือ / iPad / คอม

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)

## ตัดสินใจแล้ว

เลิกบีบหน้าคอมให้เล็กลงด้วย responsive อย่างเดียว เปลี่ยนเป็น **หน้าตาแยกตามอุปกรณ์**:
มือถือ, iPad และคอม มีโครงหน้า (shell) และหน้าหลักที่ออกแบบแยกกัน
แต่ **ข้อมูลและ logic ใช้ชุดเดียวกัน** (store, ฟังก์ชันบันทึก/โหลด, การจอง) เพื่อไม่ให้เกิดบั๊กสองชุด

## ปัญหาจากภาพหน้าจอ (Admin Builder บน iPhone 16 Pro Max 440×956)

| ที่เห็นในภาพ | เวอร์ชันมือถือจะเป็นยังไง |
|---|---|
| header ตัดคำ "HuaLonM/arket", "Ad/mi/n" เรียงแนวตั้ง | แถบบนสูง 48px: ชื่อตลาดบรรทัดเดียว (ตัด …), ไอคอนแจ้งเตือน, รูปผู้ใช้ เมนูอื่นอยู่แถบล่าง |
| แถวสถิติล้น 2 บรรทัด + แถวปุ่ม (30×20ม., จัดการโซน, +, บันทึกผัง) ซ้ำกับแถบล่าง | สถิติเหลือป้ายเดียว "1 แผง · ว่าง 1" แตะเพื่อดูเต็ม, ปุ่มไม่ซ้ำ บันทึกอยู่แถบบน ที่เหลือเข้า "⋯" |
| ผังไม่พอดีจอ เห็นแค่ป้ายขนาดตลาด ไม่เห็นแผงเลย | ผังเต็มพื้นที่ที่เหลือ เปิดมา "พอดีจอ" อัตโนมัติ |
| แผงข้อมูลตอนเลือกแผงถูกบีบไปมุมขวาล่าง ทุกคอลัมน์ตัวอักษรเรียงแนวตั้งทีละตัว ปุ่ม "แก้ไขรายละเอียด" ก็แนวตั้ง | bottom sheet กว้างเต็มจอ ข้อมูลเรียงเป็นแถว "ป้าย: ค่า" ปุ่มกว้างเต็ม ไม่มีทางตัดคำแนวตั้ง |
| แถบล่างตัวเล็กมาก | แถบล่างปุ่ม 48px ไอคอน + ป้าย อ่านได้ |

## ส่วนหัว (ใช้ทุกส่วน)

```
คุณคือนักพัฒนา Vue 3 + Pinia + Vite + Tailwind CSS ที่ทำงานใน repo "Dynamic Market Stall Booking System"
(ระบบจองแผงตลาด: ผังตลาดที่ลูกค้าดูและจอง, หน้า Admin Builder แก้ผังแบบลากวาง, หน้า Members, Customer Map)

การตัดสินใจ: แยกหน้าตาตามอุปกรณ์ 3 เวอร์ชัน (phone / tablet / desktop) ไม่ใช่แค่ responsive
- desktop = หน้าตาปัจจุบันบนคอม ต้องไม่เปลี่ยน
- tablet = ออกแบบสำหรับ iPad ใช้นิ้ว (แนวตั้งและแนวนอน)
- phone = ออกแบบสำหรับมือถือใช้มือเดียว เหมือนแอปมือถือ
- ข้อมูลและ logic ใช้ชุดเดียว: ทั้ง 3 เวอร์ชันเรียก store / composable / ฟังก์ชันเดิม ห้ามก๊อป logic ไปไว้ 3 ที่
  ถ้า logic อยู่ใน component ใหญ่ ให้ย้ายส่วนที่ไม่เกี่ยวกับ Firestore (state การเลือก, ซูม, โหมด) ออกมาเป็น
  composable ที่ทั้ง 3 เวอร์ชันใช้ร่วมกัน

โค้ดตอนนี้: ถูก reset ไป commit ก่อน 2026-10-10 แล้วมีงาน mobile บางส่วนทำต่อจากนั้น (เช่น แถบล่างบนมือถือ)
ห้ามเดา ให้ดูโค้ดจริงและ git log ก่อนเสมอ ของที่ทำไว้แล้วและใช้ได้ ให้ใช้ต่อ ไม่ทำซ้ำ

กติกา:
1. ห้ามแก้โครงข้อมูล Firestore, firestore.rules, firebase.json, .env, และโค้ดบันทึก/โหลดผังและการจอง
   (saveLayoutToFirestore, onSnapshot, stallSync, action ใน store ที่อ่าน/เขียน Firestore)
   ทุกเวอร์ชันเรียกฟังก์ชันเดิม ถ้าจำเป็นต้องแก้ ให้หยุดถามผมก่อน
2. ห้ามตัดฟีเจอร์: ทุกอย่างที่ทำได้บนคอม ต้องทำได้บน iPad และมือถือ (อาจอยู่ในเมนู "⋯" ได้)
3. desktop ต้องหน้าตาและพฤติกรรมเหมือนเดิม (ถ่ายภาพเทียบก่อน/หลังที่ 1440×900)
4. ห้ามเพิ่ม dependency ใหม่ (ถามก่อนถ้าจำเป็นจริง)
5. ข้อความไทย รองรับ dark mode ปุ่มบนมือถือ/iPad สูง ≥44px, input font ≥16px,
   ห้ามมีข้อความที่ตัดคำจนเหลือ 1–2 ตัวอักษรต่อบรรทัด (ใช้ whitespace-nowrap + truncate หรือจัด layout ใหม่)
6. ใช้ 100dvh และ env(safe-area-inset-*) แทน 100vh
7. ก่อนทุก commit รัน npm run build ต้องผ่าน และ lint / test:unit ถ้ามี ถ้ารันไม่ได้ให้บอกตรง ๆ
8. commit ย่อย ข้อความขึ้นต้น "feat(device): ..." หรือ "fix(device): ..."
9. ห้าม git push, ห้าม firebase deploy, ห้าม force push จนกว่าผมสั่ง
10. ทดสอบที่: phone 375×667, 390×844, 440×956 / tablet 768×1024, 820×1180, 1024×768, 1180×820 / desktop 1440×900
    ถ้ารัน Playwright หรือ headless browser ได้โดยไม่เพิ่ม dependency ให้ถ่ายภาพเก็บไว้ที่ docs/device-ux/
11. จบแต่ละส่วน สรุป: ทำอะไร, ไฟล์ที่แก้, ยังไม่ได้ทำอะไร, วิธีลองบนมือถือ/iPad จริงทีละขั้น
```

## ส่วน 1: ตัวตรวจอุปกรณ์ + โครงหน้า 3 แบบ

```
ส่วน 1: ทำตัวเลือกเวอร์ชันและโครงหน้า (shell) 3 แบบ

1. useDevice() คืน device: 'phone' | 'tablet' | 'desktop' (reactive)
   - phone: ความกว้าง < 640px
   - tablet: 640–1279px และเป็นจอสัมผัส (matchMedia('(pointer: coarse)')) หรือ iPad
     (iPadOS แจ้งตัวเป็น Mac: ตรวจ navigator.maxTouchPoints > 1 ร่วมด้วย)
   - desktop: ที่เหลือ (รวมคอมจอแคบที่ใช้เมาส์ 640–1279px ให้เป็น desktop)
   - คำนวณใหม่เมื่อหมุนจอ/ย่อหน้าต่าง (debounce ~150ms) และ removeEventListener ตอน unmount
   - บังคับเวอร์ชันได้: ?view=phone|tablet|desktop และเมนู "เปลี่ยนมุมมอง" ในเมนูผู้ใช้
     จำค่าใน localStorage (ครอบ try/catch) ปุ่ม "กลับเป็นอัตโนมัติ"
   - unit test ของกฎเลือกเวอร์ชัน
2. App เลือก shell ตาม device: <component :is="shell"> โหลดแบบ defineAsyncComponent
   เพื่อไม่ให้มือถือโหลดโค้ดของคอมทั้งหมด สลับ shell แล้ว state ใน store ต้องไม่หาย
3. PhoneShell:
   - แถบบนสูง 48px + safe-area-top: ชื่อตลาด (บรรทัดเดียว truncate), ปุ่มแจ้งเตือน, รูป/ตัวอักษรย่อผู้ใช้
     แตะรูปเปิด sheet: ชื่อ, บทบาท, dark mode, เปลี่ยนมุมมอง, ออกจากระบบ
   - แถบล่าง (tab bar) สูง 56px + safe-area-bottom ไอคอน + ป้ายไทย ตามสิทธิ์:
     admin: ผัง (Builder), สมาชิก, ผังลูกค้า, เพิ่มเติม  / ลูกค้า: ผังตลาด, การจองของฉัน, แจ้งเตือน, บัญชี
     (ใช้เฉพาะหน้าที่มีอยู่จริง) หน้าที่มีแถบเครื่องมือของตัวเอง (เช่น Builder) ซ่อน tab bar ได้
     และมีปุ่มย้อนกลับที่แถบบนแทน
   - สถานะ Firestore Online/Offline เป็นจุดสีเล็ก ๆ ข้างชื่อ ไม่ใช่ป้ายใหญ่
4. TabletShell:
   - แถบนำทางแนวตั้งด้านซ้าย (navigation rail) กว้าง 72px ไอคอน + ป้ายสั้นใต้ไอคอน
     ด้านล่างของ rail: แจ้งเตือน, dark mode, ผู้ใช้
   - ไม่มี header ใหญ่ ให้เนื้อหาได้ความสูงเต็ม
5. DesktopShell = layout เดิม ไม่แก้ (แค่ย้ายเข้าไฟล์ ถ้าจำเป็น)

ทดสอบ: 440×956 ไม่มีข้อความตัดคำใน header, 820×1180 rail ด้านซ้ายใช้ได้, 1440×900 เหมือนเดิมทุกพิกเซล,
?view=phone บนคอมแล้วเห็นเวอร์ชันมือถือ, หมุน iPad แล้วไม่ค้าง
```

## ส่วน 2: Admin Builder เวอร์ชันมือถือ

```
ส่วน 2: สร้าง AdminBuilderPhone ออกแบบใหม่สำหรับมือถือ ใช้ composable/store เดียวกับเวอร์ชันคอม
ห้ามแตะโค้ดบันทึก/โหลด ปุ่มบันทึกเรียกฟังก์ชันเดิม

หน้าตา:
┌──────────────────────────────┐
│ ←  ผังตลาด   ↶ ↷  ●  [บันทึก] │ แถบบน 48px (● = สถานะบันทึก: เทา=บันทึกแล้ว ส้ม=ยังไม่บันทึก)
│ 1 แผง · ว่าง 1 · 30×20ม.  ▾   │ ป้ายสรุปบรรทัดเดียว แตะเปิด sheet สถิติเต็ม
├──────────────────────────────┤
│                              │
│      ผังเต็มพื้นที่ (พอดีจอ)      │
│                    [⤢]       │ ปุ่มพอดีจอลอยมุมขวาล่าง
├──────────────────────────────┤
│ [＋แผง] [▣วัตถุ] [#Snap] [⋯]  │ แถบเครื่องมือล่าง 56px ไอคอน + ป้าย
└──────────────────────────────┘

เมื่อเลือกแผง/วัตถุ แถบล่างถูกแทนด้วย sheet:
┌──────────────────────────────┐
│ ▬                            │
│ แผง S-01 · โซนอาหาร     ว่าง  │
│ ขนาด 7.5 × 4 ม. · ราคา ฿500   │
│ [หมุน] [สำเนา] [ลบ] [แก้ไข ︿] │
└──────────────────────────────┘
ปัด/แตะ "แก้ไข" ขยายเป็นฟอร์มเต็มจอ (ป้ายเหนือช่อง ช่องกว้างเต็ม ปุ่ม −/+ ข้างช่องตัวเลข)

1. ผังกินพื้นที่ทั้งหมดระหว่างแถบบนกับแถบล่าง เปิดมาพอดีจออัตโนมัติ fit ใหม่เมื่อหมุนจอ
   ป้ายขนาดตลาดย้ายไปอยู่ในป้ายสรุป ไม่ลอยทับผัง
2. gesture: แตะ = เลือก, ลากแผงที่เลือกอยู่ = ย้าย, ลากพื้นว่าง/แผงที่ยังไม่เลือก = เลื่อนผัง,
   สองนิ้ว = ซูม, กดค้าง = เลือก + เปิด sheet  (ระยะขยับ 8px แยกแตะกับลาก, pointercancel คืนตำแหน่งเดิม)
   ใช้ระบบ gesture ที่มีอยู่ถ้าทำไว้แล้ว ไม่ทำซ้อน
3. จุดจับปรับขนาด ≥24px มองเห็น พื้นที่แตะ 44px ขนาดคงที่ไม่ขึ้นกับซูม
4. "+ แผง" วางแผงใหม่กลางจอที่เห็น เลือกให้ทันที เปิด sheet
5. "วัตถุ" เปิด sheet กริดไอคอน + ชื่อไทย แตะครั้งเดียววาง
6. "⋯" เปิด sheet: ขนาดตลาด, จัดการโซน, ตั้งค่า Snap, ล้าง/รีเซ็ตผัง (มี dialog ยืนยัน), เปลี่ยนมุมมอง
   ทุกอย่างที่เวอร์ชันคอมทำได้ต้องอยู่ที่นี่หรือในแถบ
7. sheet และฟอร์มทุกอันกว้างเต็มจอ ห้ามมีคอลัมน์ข้างกันที่บีบจนตัวอักษรแนวตั้ง
8. เตือนทับกัน/หลุดขอบ: กรอบแดง + ข้อความใน sheet
9. undo/redo: ถ้ายังไม่มี ทำใน useLayoutEditor เก็บ snapshot ในหน่วยความจำ (ไม่เกี่ยว Firestore) สูงสุด 50 ขั้น
   ล้างเมื่อโหลดผังใหม่ ถ้าต้องแตะโค้ด save/sync ให้หยุดถาม

ทดสอบที่ 375×667 และ 440×956: เปิดแล้วเห็นแผงทั้งหมด, เพิ่มแผง -> ลาก -> แก้ราคา -> บันทึก -> รีเฟรช ตำแหน่งตรง,

## ส่วน 6: ตรวจอัตโนมัติและสรุป

```
ส่วน 6: ตรวจทั้งแอปทุกอุปกรณ์

1. ถ้ารัน Playwright/headless ได้โดยไม่เพิ่ม dependency: สคริปต์ที่เปิดทุกหน้าหลัก (และ pop up หลัก) ทุกขนาดจอ

   (a) document ไม่มี scroll แนวนอน
   (b) ไม่มี element ที่มีข้อความ ≥3 ตัวอักษรแต่กว้างน้อยกว่า 2 ตัวอักษรจนตัดเป็นแนวตั้ง
       (เช่น วัด getClientRects() ของ text ว่ามีบรรทัดเกินจำนวนตัวอักษร/2)
   (c) ปุ่มบน phone/tablet สูง ≥44px
   (d) sheet/modal อยู่ใน viewport ทั้งหมด
   ถ่ายภาพเก็บที่ docs/device-ux/<หน้า>-<อุปกรณ์>-<ขนาด>.png (ไม่ commit ภาพถ้ารวมเกิน 1 MB)
   ถ้าทำไม่ได้ให้บอกและให้รายการตรวจมือแทน

3. desktop 1440×900 เทียบภาพก่อน/หลัง ต้องเหมือนเดิม
