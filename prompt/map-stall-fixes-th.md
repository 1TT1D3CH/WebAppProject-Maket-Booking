# Prompt: แก้ผังตลาด 3 เรื่อง (แผงเล็ก, admin แก้ผังยังไม่บันทึก, ดูว่าแผงที่จองแล้วขายอะไร)

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)
ใช้แทน `small-stall-label-th.md` (เรื่องแผงเล็กเปลี่ยนเป็นแสดงแค่ชื่อแผง)

## 3 เรื่องที่จะแก้

1. **แผงเล็กเกินข้อความ** ตอนนี้ชื่อโซนล้นออกนอกแผง และ "จองแล้ว" ถูกบีบจนเรียงแนวตั้งทีละตัว
   ให้เปลี่ยนเป็น: ถ้าข้อความไม่พอดีแผง ให้ตัดรายละเอียดออกให้หมด เหลือแค่ชื่อแผง (เช่น "S-02")
2. **admin ลาก/ย่อขยายแผงยังไม่กดบันทึก แต่ลูกค้าเห็นการเปลี่ยนแปลงทันที**
   ให้เปลี่ยนเป็น: ระหว่างแก้ ลูกค้าเห็นผังเดิม ลูกค้าจะเห็นผังใหม่ก็ต่อเมื่อ admin กดบันทึกแล้วเท่านั้น
3. **ลูกค้ากดดูแผงที่จองแล้ว ว่าขายอะไร** เพื่อประกอบการตัดสินใจเลือกแผง
   แสดงแค่ชื่อร้านและประเภทสินค้า ไม่แสดงชื่อจริง เบอร์โทร หรือข้อมูลส่วนตัวของผู้จอง

## แบบที่ตั้งเป้า

```
แผงที่พอ                    แผงเล็ก            ลูกค้าแตะแผงที่จองแล้ว
┌──────────────┐          ┌──────┐          ┌──────────────────────┐
│ S-02    ฿500 │          │ S-02 │          │ S-02  · จองแล้ว       │
│ โซนอาหาร &…  │          └──────┘          │ ร้าน: ข้าวมันไก่ป้าแดง  │
│ [จองแล้ว]     │          (สีแผงบอกสถานะ)     │ ขาย: อาหารคาว         │
└──────────────┘                            │ วันที่: 12-14 ต.ค.     │
                                            │              [ปิด]    │
admin กำลังลากแผง (ยังไม่บันทึก)                └──────────────────────┘
→ ลูกค้ายังเห็นตำแหน่งเดิม
admin กด "บันทึก" → ลูกค้าเห็นตำแหน่งใหม่
```

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo แล้ววาง prompt ด้านล่างทั้งก้อน
2. แนบภาพหน้าจอแผงที่ข้อความล้น (ภาพในเธรดนี้) ไปด้วย
3. agent จะสำรวจแล้วหยุดให้ดูแผนก่อนลงมือ โดยเฉพาะเรื่องที่ 2 และ 3 ที่อาจต้องเพิ่มฟิลด์ใน Firestore
4. agent commit ให้ แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง ถ้าแก้ firestore.rules ต้อง deploy rules ด้วย (agent จะบอกคำสั่ง)

## Prompt (คัดลอกทั้งก้อน)

```
คุณคือนักพัฒนา Vue 3 + Pinia + Vite + Tailwind CSS + Firebase (Firestore, Auth, Hosting)
ที่ทำงานใน repo "Dynamic Market Stall Booking System"

งาน: แก้ผังตลาด 3 เรื่อง ทำตามลำดับ เรื่องละกลุ่ม commit

เรื่อง A: แผงเล็กเกินข้อความ (ดูภาพที่แนบ)
- อาการ: ชื่อโซน "โซนอาหาร &..." ล้นออกนอกแผง, ป้าย "จองแล้ว" ถูกบีบจนเรียงแนวตั้งทีละตัวห้อยนอกแผง
- ที่ต้องการ: ถ้าข้อความทั้งหมด (ชื่อโซน, ราคา, ขนาด, ป้ายสถานะ ฯลฯ) ไม่พอดีกรอบแผง
  ให้ซ่อนรายละเอียดทั้งหมด เหลือแค่ชื่อแผง/รหัสแผงบรรทัดเดียว สถานะดูจากสีแผงที่มีอยู่แล้ว
  ถ้าแม้แต่ชื่อแผงก็ไม่พอ ให้ย่อฟอนต์ได้ถึง ~10px บนจอ ถ้ายังไม่พอให้ตัดท้ายเป็น "…" (ห้ามขึ้นบรรทัดใหม่)
- แผงที่ที่พอ แสดงเหมือนเดิม

เรื่อง B: admin ลาก/ย่อขยาย/แก้แผงยังไม่กดบันทึก แต่ลูกค้าเห็นการเปลี่ยนแปลง realtime
- ที่ต้องการ: ลูกค้า (และผู้ใช้ที่ไม่ใช่ admin) เห็นเฉพาะผังที่ admin กดบันทึกแล้ว
  การลาก ย่อขยาย หมุน เพิ่ม ลบ แก้ข้อมูลแผง/โซน/วัตถุ ระหว่างแก้ ต้องอยู่แค่ในเครื่อง admin
  จนกว่าจะกด "บันทึก" แล้วลูกค้าเห็นผังใหม่ทั้งชุดพร้อมกัน (ไม่ใช่ทีละแผง)
- สาเหตุที่เป็นไปได้ (ต้องยืนยันจากโค้ดจริง):
  (1) builder เขียน Firestore ทุกครั้งที่ลาก (autosave / debounce / dirtyStallsMap flush)
  (2) หน้าลูกค้ากับ builder ใช้ Pinia state ตัวเดียวกัน (กรณีเปิดในเครื่องเดียว/แท็บเดียว)
  (3) stallSync เขียนแผงที่ "dirty" ขึ้นไปก่อนกดบันทึก
- ทางแก้ที่ต้องการ:
  - builder แก้ใน draft state ของตัวเอง (สำเนา) ไม่เขียน Firestore จนกว่ากด "บันทึก"
  - กด "บันทึก" เขียนทั้งชุดใน writeBatch เดียว (แผง + doc ผัง) ให้ลูกค้าเห็นเปลี่ยนพร้อมกัน
  - ถ้าตอนนี้มี autosave ให้เอาออก หรือถ้าอยากเก็บไว้กันงานหาย ให้เก็บ draft ใน localStorage
    ของเครื่อง admin แทน (ไม่ใช่ Firestore ที่ลูกค้าฟังอยู่)
  - มีสถานะ "มีการแก้ไขที่ยังไม่บันทึก" ให้ admin เห็น, ปุ่ม "ยกเลิกการแก้ไข" คืนเป็นผังที่บันทึกล่าสุด,
    เตือนก่อนออกจากหน้า/ปิดแท็บถ้ายังไม่บันทึก (beforeunload + router guard)
  - ระหว่าง admin แก้ ถ้ามีการจองใหม่เข้ามา (สถานะแผงเปลี่ยนจาก Firestore) ต้องอัปเดตสถานะในผังของ admin
    โดยไม่ทับตำแหน่ง/ขนาดที่ admin กำลังแก้ และตอนบันทึกห้ามเขียนทับสถานะการจองด้วยค่าเก่า
    (บันทึกเฉพาะฟิลด์ผัง เช่น x, y, w, h, rotation, zone, ชื่อ, ราคา ไม่แตะฟิลด์การจอง)
  - หน้าลูกค้าแสดงจากข้อมูล Firestore ที่บันทึกแล้วเท่านั้น ห้ามอ่าน draft ของ builder
- ถ้าต้องเปลี่ยนโครงข้อมูล Firestore (เช่น แยก draft/published) ให้หยุดเสนอแผนก่อน
  ทางที่อยากได้คือไม่ต้องเพิ่มโครงใหม่ แค่ไม่เขียนจนกว่าจะกดบันทึก

เรื่อง C: ลูกค้าแตะแผงที่จองแล้ว เห็นว่าขายอะไร
- ตอนนี้แผงที่จองแล้วอาจแตะไม่ได้หรือแสดงแค่ "จองแล้ว" ให้แตะได้และเปิดรายละเอียดแบบอ่านอย่างเดียว:
  รหัส/ชื่อแผง, โซน, ขนาด, สถานะ, ชื่อร้าน, ประเภทสินค้า, ช่วงวันที่ที่ถูกจอง (ถ้าระบบจองรายวัน)
  ไม่มีปุ่มจอง (หรือถ้าจองรายวัน ให้ยังจองวันที่ว่างได้ตามเดิม)
- ความเป็นส่วนตัว (สำคัญ): ห้ามแสดงหรือส่งให้ลูกค้าคนอื่นอ่านได้ ซึ่งชื่อจริง เบอร์โทร อีเมล
  เลขบัตร รูปสลิป ของผู้จอง เปิดเผยได้เฉพาะชื่อร้านและประเภทสินค้า
- ข้อมูลการจองส่วนตัวน่าจะอยู่ใน bookings/{bookingId} ที่ลูกค้าคนอื่นอ่านไม่ได้ (ยืนยันจากโค้ดและ rules)
  ห้ามเปิด rules ให้ลูกค้าอ่าน bookings ทั้ง doc ทางที่เสนอ:
  - ตอนยืนยันการจอง (ที่เดียวกับที่ตั้งสถานะแผงเป็นจองแล้ว) เขียนสำเนาข้อมูลสาธารณะ
    { shopName, productType } ลงที่แผง หรือ bookingLocks ที่เกี่ยวข้อง (ที่ลูกค้าอ่านได้อยู่แล้ว)
  - ตอนยกเลิก/หมดอายุการจอง ลบสำเนานั้นด้วย
  - rules: อนุญาตให้เขียนฟิลด์เหล่านี้เฉพาะผู้ที่เขียนการจองนั้นได้อยู่แล้ว (เจ้าของการจอง/admin) จำกัดชนิดและความยาว
  - ถ้าผู้จองไม่ได้กรอกชื่อร้าน/ประเภทสินค้า แสดง "ไม่ได้ระบุ"
  - การจองเก่าที่มีอยู่แล้วจะยังไม่มีสำเนา: เสนอวิธีเติมย้อนหลัง (เช่น ปุ่มให้ admin กดเติม) แต่ห้ามรันเอง
- ถ้าการเพิ่มฟิลด์นี้ต้องแก้ firestore.rules ให้เพิ่ม test ของ rules ด้วย และหยุดให้ผมดูแผนก่อนแก้

กติกา:
1. ห้ามแตะ .env, firebase.json, ห้ามลบหรือแก้ข้อมูล Firestore จริง, ห้ามรันสคริปต์ migrate เอง
2. ห้ามเปลี่ยนขั้นตอนการจอง การชำระเงิน การตรวจสลิป นอกจากที่เรื่อง C ต้องเพิ่มการเขียนสำเนาข้อมูลสาธารณะ
3. ห้ามเพิ่ม dependency ใหม่ (ถามก่อนถ้าจำเป็นจริง)
4. ข้อความไทย รองรับ dark mode ใช้ได้บนมือถือ/iPad (แตะแผงได้ ขนาดเป้าแตะ ≥44px สำหรับปุ่ม)
5. ก่อนทุก commit รัน npm run build ต้องผ่าน และ lint / test:unit ถ้ามี
   ถ้าแก้ firestore.rules ต้องมี test และรัน npm run test:rules (ถ้ารัน emulator ไม่ได้ให้บอกตรง ๆ ห้ามบอกว่าผ่าน)
6. commit ย่อย ขึ้นต้น "fix(stall-label): ..." / "fix(builder-draft): ..." / "feat(stall-info): ..."
7. ห้าม git push, ห้าม firebase deploy, ห้าม force push จนกว่าผมสั่ง

ขั้นที่ 1: สำรวจ (ยังไม่แก้) แล้วหยุดรอผม
- git status / git log -3 --oneline (ถ้ามีไฟล์แก้ค้างที่ไม่ใช่ของงานนี้ ห้ามแตะ ให้บอกผม)
- เรื่อง A: หา component ที่วาดแผง (ค้น "จองแล้ว", "stall", "zoneName", "<rect", "<text", "foreignObject",
  "v-stage", "v-text", "canvas", "zoom", "scale") บอกว่าวาดด้วยอะไร ไฟล์:บรรทัด และสาเหตุที่ล้น
- เรื่อง B: ไล่ว่าตอน admin ลาก/ย่อขยาย มีการเขียน Firestore ตรงไหน (ค้น saveLayoutToFirestore,
  updateDoc, setDoc, writeBatch, debounce, watch, dirtyStallsMap, stallSync, autosave)
  และหน้าลูกค้าอ่านผังจากไหน สรุปเป็นแผนภาพข้อความสั้น ๆ พร้อมไฟล์:บรรทัดที่ทำให้ลูกค้าเห็นก่อนบันทึก
- เรื่อง C: ตอนนี้แตะแผงที่จองแล้วเกิดอะไร, ข้อมูลชื่อร้าน/ประเภทสินค้าเก็บที่ไหน, ลูกค้าอ่าน path ไหนได้ตาม rules
- เสนอแผนแต่ละเรื่อง รวมถึงฟิลด์ที่จะเพิ่มและ rules ที่จะแก้ แล้วหยุดรอผมตอบ

ขั้นที่ 2: ทำเรื่อง A
- คำนวณขนาดแผงบนจอเป็น px (หลังคูณ zoom) หรือวัดขนาดข้อความจริง แล้วเลือกโหมด
  "เต็ม" (ข้อความทั้งหมดพอดี) หรือ "ชื่อแผงอย่างเดียว" ค่าเกณฑ์รวมไว้ที่ค่าคงที่จุดเดียว
- ถ้าเป็น HTML/CSS: กรอบแผง overflow:hidden, ชื่อแผง whitespace-nowrap + truncate, ห้าม break-all
  ถ้าเป็น SVG: clipPath ตามกรอบแผง และตัดข้อความเองเติม "…"
  ถ้าเป็น canvas/Konva: Text ใช้ wrap:'none' + ellipsis และซ่อน node ที่ไม่พอ
- แผงมี title / aria-label เป็นข้อความเต็ม (รหัส โซน สถานะ ราคา) ส่วน tooltip/pop up รายละเอียดเดิมยังทำงาน
- ซูมเข้า/ออก หรือหมุนจอ ต้องสลับโหมดทันทีโดยไม่หน่วง (ไม่ใช้ ResizeObserver ต่อแผงถ้าแผงเยอะ)
- unit test: ฟังก์ชันเลือกโหมดตามขนาด

ขั้นที่ 3: ทำเรื่อง B ตามแผนที่ผมตกลง
- unit test: แก้ใน draft แล้วไม่มีการเรียกเขียน Firestore จนกว่ากดบันทึก, กดบันทึกเรียก writeBatch ครั้งเดียว,
  ยกเลิกแล้ว draft กลับเป็นค่าที่บันทึกล่าสุด, snapshot สถานะการจองระหว่างแก้ไม่ทับตำแหน่งใน draft
  และการบันทึกไม่เขียนทับฟิลด์การจอง

ขั้นที่ 4: ทำเรื่อง C ตามแผนที่ผมตกลง
- unit test: แผงที่จองแล้วเปิดรายละเอียดได้และแสดงชื่อร้าน/ประเภทสินค้า, ไม่มีชื่อจริง/เบอร์ในข้อมูลที่ส่งให้ลูกค้า
- rules test: ลูกค้าอ่านสำเนาข้อมูลสาธารณะได้, อ่าน bookings ของคนอื่นไม่ได้, เขียนสำเนาของการจองคนอื่นไม่ได้

ขั้นที่ 5: ตรวจรวม
- ถ้ามี Playwright หรือรันเบราว์เซอร์ headless ได้โดยไม่เพิ่ม dependency:
  (a) แผงเล็กที่ zoom ต่ำสุด/ปกติ/สูงสุด บนจอ 375×667, 768×1024, 1440×900 ข้อความอยู่ในกรอบแผงและไม่มีป้ายสูงเกิน 1 บรรทัด
  (b) เปิด 2 หน้าต่าง (admin + ลูกค้า) admin ลากแผงยังไม่บันทึก ลูกค้าไม่เห็น, กดบันทึกแล้วลูกค้าเห็น
  ถ้าทำไม่ได้ให้บอกและให้รายการตรวจมือ

สรุปให้ผม:
1. แต่ละเรื่อง: สาเหตุ (ไฟล์:บรรทัด) -> วิธีแก้ -> test ที่พิสูจน์
2. ฟิลด์ Firestore ที่เพิ่ม และ rules ที่แก้ (ถ้ามี) พร้อมผล test:rules
3. ไฟล์ที่แก้ และรายการ commit
4. ขั้นตอนลองเองด้วย 2 หน้าต่าง (admin กับลูกค้า) ผ่าน npm run dev -- --host บนคอมและมือถือ
5. วิธีเติมชื่อร้าน/ประเภทสินค้าให้การจองเก่า (ยังไม่ต้องรัน)
6. คำสั่ง push / deploy ที่ผมต้องรันเอง เช่น firebase deploy --only firestore:rules,hosting (ยังไม่ต้องรัน)
```
