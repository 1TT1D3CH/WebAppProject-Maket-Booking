# Prompt: ทำ pop up (modal) ทุกอันให้พอดีทุกจอ

ใช้กับ repo "Dynamic Market Stall Booking System" (Vue 3 + Pinia + Vite + Tailwind + Firebase)

## ปัญหา

pop up บน iPad/มือถือ ล้นจอ หลุดขอบล่าง ปุ่มโดนตัด ตัวอักษรในปุ่มเรียงแนวตั้ง ต้องเลื่อนทั้งหน้าเพื่อหาปุ่มยืนยัน

## แบบที่ตั้งเป้า

```
มือถือ (<640px)              iPad / คอม (≥640px)
┌────────────────────┐     ┌──────────────────────────────┐
│ ชื่อ pop up      [X] │ ←ติด │        (พื้นหลังมืด)           │
├────────────────────┤     │   ┌──────────────────────┐   │
│                    │     │   │ ชื่อ pop up        [X] │   │
│  เนื้อหา            │     │   ├──────────────────────┤   │
│  (เลื่อนได้ข้างใน)    │     │   │ เนื้อหา (เลื่อนข้างใน) │   │
│                    │     │   ├──────────────────────┤   │
├────────────────────┤     │   │       [ยกเลิก] [ยืนยัน] │   │
│ [     ยืนยัน      ] │ ←ติด │   └──────────────────────┘   │
│ [     ยกเลิก      ] │     │   สูงไม่เกิน 90% ของจอ          │
└────────────────────┘     └──────────────────────────────┘
เต็มจอ หรือ sheet จากล่าง
```

## วิธีใช้

1. เปิด coding agent ที่ root ของ repo แล้ววาง prompt ด้านล่างทั้งก้อน (ใช้เดี่ยว ๆ ได้ ไม่ต้องรอ mobile-tablet-ux-th.md)
2. ถ้ามีภาพหน้าจอ pop up ที่พัง แนบไปด้วย
3. agent จะหยุดให้ดูรายการ pop up ก่อนลงมือ แล้ว commit ให้ แต่ **ไม่ push ไม่ deploy** จนกว่าคุณสั่ง
4. ถ้าทำ mobile-tablet-ux-th.md ส่วน 4 ไปแล้ว prompt นี้จะเก็บตกส่วนที่เหลือ

## Prompt (คัดลอกทั้งก้อน)

```
คุณคือนักพัฒนา Vue 3 + Pinia + Vite + Tailwind CSS ที่ทำงานใน repo "Dynamic Market Stall Booking System"

งาน: ทำ pop up ทุกอันในแอป (modal, dialog ยืนยัน, แผงข้อมูลที่เด้งขึ้น, bottom panel, dropdown ใหญ่)
ให้พอดีจอทุกขนาด: มือถือ 375×667, 390×844, iPad แนวตั้ง 768×1024 / 820×1180,
iPad แนวนอน 1024×768 / 1180×820, คอม 1440×900 และ iPhone แนวนอน 667×375

อาการที่เห็นจริงบน iPad: แผงข้อมูลด้านล่างตอนเลือกวัตถุในหน้า Admin Builder หลุดขอบล่างจอ,
ปุ่ม "แก้ไขวัตถุ" ตัวอักษรเรียงแนวตั้งทีละพยางค์, ปุ่มยืนยันต้องเลื่อนหา

สำคัญ: โค้ดถูก reset กลับไป commit ก่อน 2026-10-10 ห้ามเดาว่ามี BaseModal หรือ component กลาง
จนกว่าจะเห็นในโค้ดจริง

กติกา:
1. งาน UI เท่านั้น ห้ามแก้โครงข้อมูล Firestore, firestore.rules, firebase.json, .env,
   และโค้ดบันทึก/โหลดผังหรือการจอง (saveLayoutToFirestore, onSnapshot, stallSync, action ใน store ที่อ่าน/เขียน
   Firestore) เพราะมีอีกงานกำลังแก้อยู่ pop up เรียกฟังก์ชันเดิมตามเดิม ถ้าจำเป็นต้องแก้ให้หยุดถามผมก่อน
2. ห้ามตัดช่องกรอกหรือปุ่มใดทิ้ง ห้ามเปลี่ยนลำดับขั้นตอนการจอง
3. ห้ามเพิ่ม dependency ใหม่ (ถามก่อนถ้าจำเป็นจริง)
4. ข้อความไทย รองรับ dark mode
5. ก่อนทุก commit รัน npm run build ต้องผ่าน และ lint / test:unit ถ้ามี ถ้ารันไม่ได้ให้บอกตรง ๆ
6. commit ย่อย ข้อความขึ้นต้น "fix(modal): ..." หรือ "feat(modal): ..."
7. ห้าม git push, ห้าม firebase deploy, ห้าม force push จนกว่าผมสั่ง

ขั้นที่ 1: สำรวจ (ยังไม่แก้) แล้วหยุดรอผม
- git status / git log -3 --oneline (ถ้ามีไฟล์แก้ค้างที่ไม่ใช่ของงานนี้ ห้ามแตะ ให้บอกผม)
- ค้นทุก pop up: ค้น "fixed inset-0", "modal", "dialog", "Teleport", "z-50", "showModal", "isOpen",
  "v-if=\"show", แผงที่ position fixed/absolute ติดขอบล่าง
- ตาราง: ไฟล์ | pop up อะไร | ใครเห็น | ใช้ component กลางไหม | ปัญหาที่ 375 / 768 / 1024
  (ล้นแนวตั้ง, ล้นแนวนอน, ปุ่มหลุดจอ, ตัวอักษรตัดคำผิด, ความกว้าง fix เป็น px, ใช้ 100vh/h-screen,
  ไม่มี scroll ข้างใน, หน้าหลังเลื่อนตามได้, คีย์บอร์ดบังช่องกรอก)
- เสนอว่าจะทำ component กลาง หรือปรับของเดิม แล้วหยุดรอผมตอบ

ขั้นที่ 2: component กลาง BaseModal (สร้างใหม่ หรือปรับของเดิมถ้ามี)
- props: open, title, size ('sm' | 'md' | 'lg' | 'full'), mobileMode ('sheet' | 'fullscreen'),
  dismissible (default true); slots: default (เนื้อหา), footer (ปุ่ม); emit close
- โครงสร้าง flex แนวตั้ง 3 ส่วน: header (ติดบน) / body (overflow-y-auto, min-h-0) / footer (ติดล่าง)
  มีแค่ body ที่เลื่อน ปุ่มยืนยันต้องเห็นเสมอโดยไม่ต้องเลื่อน
- ขนาด:
  - <640px: mobileMode 'fullscreen' = เต็มจอ h-[100dvh] w-full ไม่มีมุมโค้ง
            mobileMode 'sheet' = ชิดล่าง กว้างเต็ม มุมบนโค้ง สูงสูงสุด 90dvh มีขีดจับด้านบน
  - ≥640px: กลางจอ กว้าง sm 400px / md 560px / lg 760px แต่ไม่เกิน calc(100vw - 32px),
            สูงสูงสุด calc(100dvh - 48px), size 'full' = เกือบเต็มจอเว้นขอบ 24px
  - ใช้ 100dvh และมี fallback 100vh
- safe area: header เว้น env(safe-area-inset-top) เมื่อเต็มจอ, footer เว้น env(safe-area-inset-bottom)
- ปุ่มใน footer:
  - มือถือ: เรียงแนวตั้ง กว้างเต็ม ปุ่มหลักอยู่บน สูง ≥44px
  - ≥640px: เรียงแนวนอนชิดขวา ปุ่มหลักขวาสุด
  - ทุกปุ่ม whitespace-nowrap ห้ามตัดคำ ถ้ายาวเกินให้ย่อข้อความหรือขึ้นบรรทัดทั้งปุ่ม
- พฤติกรรม: <Teleport to="body">, Esc ปิด, แตะพื้นหลังปิด (ถ้า dismissible), ปุ่ม X ขนาด 44px,
  role="dialog" aria-modal="true" aria-labelledby, focus ไปช่องแรก/ปุ่มปิดตอนเปิด, focus trap, คืน focus ตอนปิด
- lock scroll หน้าหลังตอนเปิด และคืนค่าตอนปิด ต้องได้บน iOS Safari ด้วย
  (เก็บ scrollY แล้วใช้ position:fixed บน body หรือวิธีที่เทียบเท่า) รองรับเปิดซ้อนกันหลายชั้น
- คีย์บอร์ดบนมือถือ: ตอน focus ช่องกรอก scrollIntoView({block:'center'}),
  ใช้ window.visualViewport ปรับความสูง/ตำแหน่ง footer ไม่ให้คีย์บอร์ดบัง
- หมุนจอหรือเปลี่ยนขนาดหน้าต่างระหว่างเปิด pop up ต้องปรับตามทันที
- ภาพ/QR ข้างในใช้ max-w-full h-auto, ตารางข้างในห่อ overflow-x-auto เฉพาะตาราง

ขั้นที่ 3: ย้าย pop up ทุกอันไปใช้ BaseModal ทีละอัน (หนึ่ง commit ต่อกลุ่มที่เกี่ยวกัน)
- แนะนำ mobileMode: ฟอร์มยาว (จอง, ล็อกอิน/สมัคร, แก้ข้อมูลแผง/วัตถุ, จัดการโซน, ตั้งค่า) = 'fullscreen'
  สั้น (ยืนยันลบ, แจ้งเตือน, รายละเอียดแผง) = 'sheet'
- ห้ามเปลี่ยน logic ข้างใน แค่ย้ายเนื้อหาเข้า slot และย้ายปุ่มเข้า footer
- ช่องกรอกข้างใน: font-size ≥16px (กัน iOS ซูม), ป้ายเหนือช่อง, กว้างเต็มบนมือถือ, type/inputmode ถูก
- ปิด pop up ที่มีข้อมูลกรอกค้าง: ถามยืนยันก่อน (เฉพาะฟอร์มที่กรอกไปแล้ว)

ขั้นที่ 4: แผงที่เด้งขึ้นแต่ไม่ใช่ modal (เช่น แผงด้านล่างตอนเลือกวัตถุ/แผงในหน้า Admin Builder,
แผงแจ้งเตือน, dropdown/เมนู)
- แผงด้านล่าง: กว้างเต็มจอบนมือถือและ iPad แนวตั้ง, ชิดล่างเหนือ safe area, สูงสูงสุด 50dvh
  เนื้อหาเลื่อนข้างใน ห้ามหลุดขอบจอ ปุ่ม (แก้ไข / หมุน / ลบ) ขนาด ≥44px ห้ามตัดคำ
  ถ้าที่ไม่พอให้ข้อมูลขึ้นบรรทัดใหม่ ไม่ใช่บีบปุ่ม
- ผังด้านหลังต้องเว้นที่ให้แผงนี้ หรือเลื่อนให้วัตถุที่เลือกไม่ถูกบัง
- dropdown/เมนู: ใช้ Teleport + คำนวณตำแหน่ง ไม่ให้ล้นขอบขวา/ล่าง (พลิกขึ้นบนหรือชิดซ้ายเมื่อไม่พอ)
  บนมือถือเปลี่ยนเป็น sheet จากล่าง
- z-index: กำหนดเป็นลำดับเดียวทั้งแอป (เช่น header 30, แผงล่าง 40, dropdown 50, modal 60, toast 70)
  ไม่ให้ pop up ไปอยู่ใต้ header หรือแถบเครื่องมือ

ขั้นที่ 5: ตรวจ
- ถ้ามี Playwright หรือรันเบราว์เซอร์ headless ได้โดยไม่เพิ่ม dependency: เปิด pop up ทุกอันที่ทุกขนาดจอข้างบน
  ตรวจอัตโนมัติว่า (a) กล่อง pop up อยู่ใน viewport ทั้งหมด (b) ปุ่มใน footer มองเห็นโดยไม่เลื่อน
  (c) ไม่มีปุ่มที่ความสูงเกิน 2 เท่าของ line-height (ตัดคำ) (d) document ไม่มี scroll แนวนอน
  ถ้าทำไม่ได้ให้บอกและให้รายการตรวจมือ
- unit test ของ BaseModal: เปิด/ปิด, Esc, คลิกพื้นหลัง, dismissible=false, lock/unlock scroll ซ้อนกัน 2 ชั้น

สรุปให้ผม:
1. ตาราง: pop up | ไฟล์ | ก่อน (ปัญหา) | หลัง | mobileMode
2. ไฟล์ที่สร้าง/แก้ และรายการ commit
3. ยืนยันด้วย git diff --stat ว่าไม่ได้แก้ firestore.rules และโค้ดบันทึก/โหลด
4. วิธีลองบนมือถือ/iPad จริงผ่าน npm run dev -- --host: เปิด pop up แต่ละอัน, หมุนจอ, แตะช่องกรอกให้คีย์บอร์ดขึ้น
5. คำสั่ง push / deploy ที่ผมต้องรันเอง (ยังไม่ต้องรัน)
```
