 3. ข้อควรรู้ / ข้อจำกัด
-------------------------------------------------------------------------------
  - ยังไม่ได้ทดสอบกับ Firebase จริงหรือเปิด browser: ล็อกอิน username, หน้า Members,
    เปลี่ยนรหัสผ่านบังคับ ตรวจแค่ build + unit test ควรลองด้วยตัวเองก่อน deploy
  - ไม่ได้รัน test:rules (ต้องใช้ firebase emulator)
  - Members: owner เปลี่ยนสิทธิ์ผู้อื่นผ่านหน้านี้ได้ ตรงกับ rules ของ main
    (admin อ่านรายชื่อได้ แต่เปลี่ยน role ไม่ได้)
  - บัญชี owner/admin สร้างด้วย  npm run seed:staff -- --username owner001 --role owner
    (ต้องมี credential ของ Firebase Admin ในเครื่อง: gcloud auth application-default login
    หรือ GOOGLE_APPLICATION_CREDENTIALS) ข้อมูลโปรไฟล์ที่ script เขียน (mustChangePassword,
    superUser) ควรตรวจกับ rules ของ main ก่อนใช้จริง
  - package-lock.json เปลี่ยนมาก (เพิ่ม firebase-admin และ dependency ย่อย)
  - ไม่ได้ commit: .agents/, .claude/, skills-lock.json (ไฟล์เครื่องมือ ไม่ใช่โค้ดโปรเจกต์)
  - ข้อความ commit ของ main เดิมไม่ถูกแก้ history ใด ๆ

 4. สิ่งที่คุณต้องทำเอง
-------------------------------------------------------------------------------
  1) ตรวจ commit: git log -1 --stat   ถ้าพอใจค่อย git push
  2) ลองรัน npm run dev: ล็อกอินอีเมล, ล็อกอิน Google, (ถ้ามีบัญชี staff) ล็อกอิน username,
     เมนู Members, ปุ่มเปลี่ยนรหัสผ่าน
  3) Deploy:  npm run deploy   (build + hosting + firestore rules/indexes)
     แล้วเปิดเว็บใน Incognito ต้องไม่เห็นปุ่ม/modal ตั้งค่า Firebase
  4) Firebase Console: เปิด Email/Password และ Google ใน Authentication,
     เพิ่มโดเมนเว็บใน Authorized domains
  5) ถ้า .env เคยถูก push ขึ้น GitHub ในประวัติเก่า ให้ตรวจว่าไม่มีความลับอื่นปนอยู่
     (ค่า VITE_FIREBASE_* ไม่ใช่ความลับ)
  6) เมื่อมั่นใจว่าไม่ต้องใช้แล้ว ลบ tag pre-abort-backup และโฟลเดอร์สำรองใน scratchpad
