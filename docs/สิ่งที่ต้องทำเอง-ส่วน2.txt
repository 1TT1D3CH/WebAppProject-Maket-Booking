สิ่งที่คุณต้องทำเอง หลังทำ "ส่วน 2: จองตามวัน/รอบตลาด" เสร็จ
=========================================================
(ผม commit โค้ดให้แล้ว แต่ไม่ได้ push และไม่ได้ deploy)

1) Deploy rules + indexes + โค้ดเว็บ "พร้อมกันในคำสั่งเดียว"
   npm run deploy
   ถ้า deploy แยกกัน โค้ดเก่า/ใหม่จะไม่ตรงกับ rules แล้วจอง/ยกเลิกไม่ผ่าน (Missing or insufficient permissions)

2) รอ index ใหม่เป็นสถานะ Enabled
   Firebase Console > Firestore > Indexes ต้องมี 2 ตัวของ bookingLocks:
   (stallId, date) และ (roundId, date)
   ก่อน Enabled หน้าจองจะขึ้น "ดัชนีฐานข้อมูลยังสร้างไม่เสร็จ" ให้รอสักครู่

3) ตั้งค่าตลาดครั้งแรก (ต้องล็อกอินเป็น admin/owner)
   เมนู "ตั้งค่าการจอง" ที่แถบบน: เลือกวันเปิดขาย, ปิดรับจองล่วงหน้า, จำนวนช่องสูงสุด (ไม่เกิน 7),
   และรอบ (ถ้าต้องการหลายรอบ) ถ้าไม่ตั้ง ระบบใช้ค่าเริ่มต้น วันละ 1 รอบ

4) ทดสอบด้วยมือในเบราว์เซอร์ (ผมยังไม่ได้เปิดดูจริง)
   - บัญชี A จองแผง A-01 วันเสาร์ บัญชี B จองแผงเดียวกันวันอาทิตย์ได้ ส่วนวันเสาร์ B จองไม่ได้
   - สลับวันบนแถบเลือกวันเหนือผัง สีแผงต้องเปลี่ยนตามวันทันที
   - admin อนุมัติสลิป แผงเป็น "จองแล้ว" เฉพาะวันนั้น / ปฏิเสธหรือผู้เช่ายกเลิก แผงกลับมาว่าง
   - "การจองของฉัน" และหน้าตรวจสลิปของ admin ต้องแสดง "วันที่จอง"
   - ดูบนมือถือ/iPad ว่าตัวเลือกวันในหน้าจองกดง่ายและไม่ล้นจอ

5) วาง rules ที่ใช้อยู่จริงจาก Firebase Console (Firestore > Rules) เพื่อเทียบกับ firestore.rules
   ในโปรเจกต์ (ค้างมาจากส่วน 0) แล้วเก็บเป็น docs/rules-deployed-<วันที่>.rules

6) การจองเดิมที่ยังกันแผงแบบไม่มีวัน (stall.status เป็น booked/pending) จะยังกันแผงทุกวัน
   และจองตามวันไม่ได้จนกว่า admin ปล่อยแผงนั้น (ตามแผน "การจองแบบเดิม")
   ตัดสินใจว่าจะปล่อยแผงเหล่านั้นเมื่อไร

7) ข้อจำกัดที่ควรรู้
   - rules ตรวจปฏิทินตลาด (วันเปิด/ปิด จองล่วงหน้า เวลาปิดรับ) ไม่ได้ ตรวจที่หน้าเว็บเท่านั้น
   - จองได้ครั้งละไม่เกิน 7 ช่อง (ข้อจำกัดจำนวนการอ่านเอกสารต่อคำสั่งเขียนของ rules)
   - ลบรอบออกจากตั้งค่า ระบบเตือนถ้ายังมีการจองอนาคตในรอบนั้น (นับสูงสุด 200)

8) ถ้าพร้อมแล้ว สั่ง "ตกลง" เพื่อเริ่มส่วน 3 (หมดเวลาจองอัตโนมัติ 30 นาที)
