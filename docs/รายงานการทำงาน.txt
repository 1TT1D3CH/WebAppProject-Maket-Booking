2) ส่วน 0: สำรวจโค้ดจริง (ไม่แก้โค้ด)
-------------------------------------

สิ่งที่พบ (โค้ดจริงต่างจากที่ prompt สมมติ):

4) ที่ยังไม่ได้ทำ / ข้อควรรู้
-----------------------------
- ยังไม่ได้เปิดหน้า "บันทึกการทำงาน" และประวัติในเบราว์เซอร์จริง (ผ่านแค่ build และ test)
- log เรื่อง "ตั้งค่าตลาด" และ "เปิด/ปิดแผง" ยังไม่ทำ เพราะอยู่ในโค้ดบันทึกผัง (saveLayoutToFirestore)
  ซึ่งห้ามแตะ ข้อเสนอ: เรียกจาก component ที่กดปุ่ม "บันทึกผัง" หลังบันทึกสำเร็จ (รอคุณตัดสินใจ)
- การเปลี่ยน role: ไม่บังคับที่ rules ของ users (doc นั้นไม่มีฟิลด์ lastAuditId)
- การจองเก่าจะไม่มีประวัติย้อนหลัง
- ตัวกรองฝั่งเซิร์ฟเวอร์ใช้ได้ครั้งละ 1 ตัว (เลขการจอง หรือ action) + ช่วงวันที่
  ส่วนชื่อคนทำและค้นเลขแผงกรองในหน้าเว็บจากแถวที่โหลดแล้ว
- owner ที่เข้า Firebase Console ยังลบ log ได้ (กันไม่ได้บน Spark)
- ต้อง deploy rules + indexes + hosting พร้อมกันในคำสั่งเดียว (ส่วน 7)
  มิฉะนั้นโค้ดเก่าที่ค้าง cache จะจอง/ยกเลิก/ส่งสลิปไม่ผ่าน
- index ใหม่ต้องเป็น Enabled ใน Console ก่อนหน้า log จะค้นได้

6) แก้บั๊ก role ใน audit log (commit b7934d6)
---------------------------------------------
อาการ: บัญชี admin/owner จอง ยกเลิก หรือส่งสลิปใหม่ด้วยตัวเองไม่ผ่าน (error สิทธิ์)

การแก้: src/services/firebaseService.js ใช้ role จริงของผู้ใช้ (selfActor)
test: เพิ่ม 1 ข้อ (admin จองเองผ่าน / ระบุเป็น tenant ไม่ผ่าน) -> rules 91/91
หมายเหตุ: ผมยังไม่ทราบอาการจริงที่ผู้ใช้เจอ จึงยืนยันไม่ได้ว่าเป็นบั๊กเดียวกัน
ถ้ายังพัง ให้ส่งข้อความ error + บัญชีที่ใช้ + ขั้นตอนที่พัง และตรวจว่า deploy rules กับ hosting พร้อมกันหรือไม่
