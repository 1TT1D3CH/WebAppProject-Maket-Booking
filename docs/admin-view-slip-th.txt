รายงาน: ให้ admin และ owner เห็นภาพสลิปโอนเงิน
วันที่: 2026-10-11
อ้างอิง: prompt/slip-verification-th.md (ส่วน 2)

======================================================================
1. สถานะตอนนี้
======================================================================
- ผู้เช่าแนบสลิปตอนจองแล้ว (commit cf7cdcb) รูปถูกย่อและเก็บใน Firestore
  ที่ collection bookingSlips/{bookingId}  (ฟิลด์ dataUrl, mime, bytes, tenantId)
- rules อนุญาตให้ admin และ owner อ่าน bookingSlips ได้แล้ว (isAdmin() รวม owner)
  และมีฟังก์ชัน getSlip(bookingId) ใน src/services/slipStorage.js พร้อมใช้
- สิ่งที่ยังไม่มี: หน้าจอฝั่ง admin/owner ที่เรียกดูรูป
  ดังนั้นตอนนี้ข้อมูลสลิปอยู่ในฐานข้อมูลแต่ยังไม่มีที่ไหนแสดงผล
- การจองใหม่จะมีสถานะ pending (แผงสีเหลือง "รอตรวจสลิป") และจะค้างอยู่
  จนกว่าจะมีหน้าตรวจสลิปให้กดอนุมัติ / ขอสลิปใหม่ / ปฏิเสธ

======================================================================
2. ดูได้ทันทีโดยไม่ต้องเขียนโค้ด (ชั่วคราว)
======================================================================
Firebase Console > Firestore Database > collection bookingSlips > เลือกเอกสาร
> คัดลอกค่า dataUrl ไปวางในแถบที่อยู่ของเบราว์เซอร์ จะเห็นรูป
ยอดที่ต้องได้รับดูที่ bookings/{id}.amountDue
ใช้ได้เฉพาะตอนฉุกเฉิน ไม่เหมาะเป็นวิธีทำงานประจำ และอนุมัติการจองไม่ได้

======================================================================
3. วิธีทำให้ถูกต้อง: เพิ่มหน้า "ตรวจสลิป" (ส่วน 2 ของ prompt)
======================================================================
3.1 ข้อมูล (composable ร่วม useSlipReview)
  - onSnapshot  bookings  where status == 'pending'  orderBy createdAt asc
  - แท็บ: รอตรวจ (pending) / ขอสลิปใหม่ (needs_slip) / ตัดสินแล้ว (approved, rejected 50 รายการล่าสุด)
  - โหลดรูปด้วย getSlip(bookingId) เฉพาะตอนเปิดรายการ และ prefetch รายการถัดไป 1 รายการ
    (ไม่โหลดรูปมากับรายการ เพราะแต่ละรูปราว 300-700 KB)
  - badge ตัวเลขจำนวนรอตรวจบนเมนู เห็นเฉพาะ admin/owner
  - ต้องเพิ่ม index ใน firestore.indexes.json:
      bookings (status ASC, createdAt ASC)
    และต้อง deploy ก่อน ไม่งั้นหน้าจะขึ้น error ระหว่าง index ยัง Building

3.2 หน้ารายละเอียด (ข้อมูลที่ใช้ตัดสิน)
  - รูปสลิป: แตะเต็มจอ, pinch-zoom / ดับเบิลแตะ, ล้อเมาส์ซูมบนคอม, หมุน 90 องศา
  - ยอดที่ต้องได้รับ (amountDue) ตัวใหญ่, แผง/โซน, ชื่อผู้เช่า ชื่อร้าน เบอร์โทร
  - checklist ติ๊กด้วยตา: ยอดตรง / ชื่อผู้รับตรง / เวลาโอนหลังเวลาจอง / ไม่ใช่สลิปซ้ำ
  - คำเตือนสีแดงถ้า slipHash ซ้ำกับ booking อื่น (query bookings where slipHash == ...)

3.3 ปุ่มตัดสิน (ทำใน batch/transaction เดียว)
  - อนุมัติ  -> booking.status = approved และแผง status = booked
  - ขอสลิปใหม่ (ต้องใส่เหตุผล) -> booking.status = needs_slip (แผงยังเป็น pending)
  - ปฏิเสธ (ต้องใส่เหตุผล) -> booking.status = rejected และแผงกลับเป็น available
  - บันทึก decidedBy = uid, decidedAt, statusReason
  - transaction อ่านสถานะล่าสุดก่อน ถ้าไม่ใช่ pending ให้แจ้ง "ถูกตรวจไปแล้ว" ไม่ทับ
  - ส่ง notification ถึงผู้เช่า (notificationStore มีอยู่แล้ว)

3.4 การจัดหน้าตามอุปกรณ์ (logic เดียวกัน)
  - มือถือ: การ์ดรายการ -> แตะเปิดเต็มจอ รูปอยู่บน ปุ่มตัดสินติดล่าง (safe-area)
  - iPad แนวนอน: รายการซ้าย รายละเอียดขวา เห็นรูปกับยอดพร้อมกัน
  - iPad แนวตั้ง: รายการเต็มจอ แตะแล้วรายละเอียดเลื่อนขึ้น
  - คอม: ตาราง + แผงรายละเอียด คีย์ลัด A อนุมัติ / R ขอสลิปใหม่ / J,K ถัดไป,ก่อนหน้า
  - เพิ่มเมนู "ตรวจสลิป" ใน Navbar และเพิ่ม activeMode ใหม่ใน App.vue
    (App.vue สลับหน้าด้วย marketStore.activeMode ไม่ได้ใช้ vue-router)

3.5 rules ที่ต้องเพิ่ม (ฝั่ง admin)
  - ปัจจุบัน admin แก้ bookings ได้ทุกฟิลด์ (allow update: if isAdmin()) ควรจำกัดเป็น
    * เปลี่ยนสถานะตามลำดับ pending -> approved / needs_slip / rejected เท่านั้น
    * ห้ามแก้ tenantId, amountDue, slipHash
    * ต้องมี decidedBy == uid, decidedAt == request.time
    * statusReason บังคับเมื่อ needs_slip / rejected (ข้อความ 1-300 ตัวอักษร)
    * สถานะแผงต้องเปลี่ยนตาม booking (ตรวจด้วย getAfter)
  - เขียน test ใน tests/firestore.rules.test.mjs ให้ครบ (tenant อนุมัติเองไม่ได้,
    admin แก้ยอดไม่ได้, owner ทำได้เท่า admin ฯลฯ)

======================================================================
4. ข้อควรระวัง
======================================================================
- เวลา deploy ต้อง deploy rules + indexes + hosting พร้อมกันในคำสั่งเดียว:
    npm run build && firebase deploy --only firestore:rules,firestore:indexes,hosting
  (ครั้งที่แล้วจองไม่ได้เพราะ rules กับโค้ดไม่ตรงกัน)
- ห้ามแตะ saveLayoutToFirestore / stallSync.js / การโหลดผัง (มีงานอื่นดูอยู่)
  ตอน admin อนุมัติ ให้เขียนสถานะแผงผ่านเส้นทางของหน้าตรวจสลิปเอง
- Firestore ฟรี 1 GiB รับสลิปได้ราวพันกว่ารูป ควรมีวิธีลบสลิปเก่าที่ตัดสินแล้วในอนาคต
  (deleteSlip มีแล้วใน slipStorage.js, rules ให้ admin ลบได้)
- ยังเป็นการตรวจด้วยตา ไม่มีการอ่านสลิปอัตโนมัติ (ต้องใช้บริการภายนอก/Blaze)

======================================================================
5. ขั้นตอนถัดไปที่เสนอ
======================================================================
1) สร้างหน้า "ตรวจสลิป" (เฉพาะดูรูป + ยอด + ข้อมูลผู้เช่า) พร้อม index และ badge
2) เพิ่มปุ่มอนุมัติ / ขอสลิปใหม่ / ปฏิเสธ พร้อม rules และ test
3) deploy rules + indexes + hosting ในคำสั่งเดียว แล้วทดสอบด้วยบัญชีทดสอบ 1 รายการ

ประมาณงาน: ข้อ 1-2 ทำต่อเนื่องได้ในรอบเดียว (ส่วน 2 ของ prompt)
