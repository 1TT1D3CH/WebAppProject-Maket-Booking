 1. โปรเจกต์นี้คืออะไร
===============================================================================

เว็บแอปจองแผงขายของในตลาดนัด (ตลาดยามเย็น Walking Street KKU) ผู้ใช้ 3 กลุ่ม
  - ผู้เช่า (tenant)   : ดูผังตลาด เลือกวัน/รอบ เลือกแผง จองหลายวันในครั้งเดียว
                          โอนเงิน (PromptPay) แนบสลิป ติดตามสถานะ ยกเลิก/ขอคืนเงิน
                          ดาวน์โหลดใบเสร็จ
  - ผู้ดูแล (admin)    : วาด/แก้ผังตลาดแบบลากวาง ตรวจสลิป อนุมัติ/ปฏิเสธ
                          จัดการยกเลิกและคืนเงิน ดูบันทึกการทำงาน (audit log)
  - เจ้าของ (owner)    : ทำได้ทุกอย่างของ admin + ดูรายงานรายได้ (ส่งออก Excel/CSV)
                          + จัดการสมาชิก/สิทธิ์ + ลบบันทึกการทำงาน

ตัวระบบเป็น Single Page Application ไม่มี server ของตัวเอง
ใช้ Firebase (Authentication + Firestore) เป็น backend ทั้งหมด
และใช้ "Firestore Security Rules" เป็นตัวบังคับกติกาทางธุรกิจแทน server

 3. สถาปัตยกรรมภาพรวม
===============================================================================

   [ เบราว์เซอร์ผู้ใช้ ]
        │  Vue 3 + Pinia (Frontend)
        │   ├─ components/  = หน้าจอ
        │   ├─ stores/      = state + logic ของแต่ละเรื่อง
        │   ├─ services/    = ฟังก์ชันคุย Firestore (transaction/batch)
        │   └─ utils/       = ฟังก์ชันล้วน (วันที่ ปฏิทิน รายได้ คืนเงิน ฯลฯ)
        ▼
   [ Firebase SDK ]  ── Auth ──►  Firebase Authentication
        │
        └── Firestore ──►  Cloud Firestore  ◄── firestore.rules (ตรวจทุกคำสั่งอ่าน/เขียน)
                             │
                             └ ข้อมูล realtime ส่งกลับมาที่ stores ผ่าน onSnapshot

หลักคิด: Frontend ทำ UI + ตรวจเบื้องต้น, Firestore Rules ตัดสินสุดท้าย
(ถ้า client ถูกแก้/ข้ามการตรวจ ฐานข้อมูลก็ยังปฏิเสธคำสั่งที่ผิดกติกา)

ลำดับเริ่มแอป
  index.html → src/main.js → โหลด App.vue แบบ dynamic (ดักข้อผิดพลาดตอนเริ่ม
  เช่น .env ไม่ครบ) → App.vue เรียก authStore.initAuth(), marketStore.initFirebaseSync(),
  slotStore.startSettings() แล้วสลับหน้าตาม marketStore.activeMode

 5. บทบาทผู้ใช้ และสิทธิ์
===============================================================================

 บทบาท   ทำอะไรได้
 ------  -----------------------------------------------------------------------
 guest   ดูผังตลาดและสถานะแผงได้ (ยังจองไม่ได้ ต้องล็อกอิน)
 tenant  จองแผง/แนบสลิป/ส่งสลิปใหม่/ยกเลิก/ขอยกเลิกพร้อมขอคืนเงิน/ดูใบเสร็จ
         ดูและลบแจ้งเตือนของตัวเอง
 admin   แก้ผังตลาด, ตั้งค่าตลาดและกติกาการจอง, ตรวจสลิป, ตัดสินยกเลิก/คืนเงิน,
         ลบการจอง, ดูสมาชิก, ดู audit log, ออกเลขใบเสร็จย้อนหลัง
 owner   เหมือน admin + รายงานรายได้/ส่งออก, เปลี่ยนสิทธิ์สมาชิก, ลบ audit log,
         ลบการจองที่ออกใบเสร็จแล้ว

การสมัครด้วยตัวเองได้ role = tenant เสมอ (rules บังคับ) ห้ามแก้ role ของตัวเอง
บัญชี admin/owner สร้างด้วยสคริปต์ scripts/seed-staff.mjs ล็อกอินด้วย "ชื่อผู้ใช้"
(แปลงเป็นอีเมลภายในโดเมน VITE_STAFF_EMAIL_DOMAIN)

 6. ฟีเจอร์หลักของระบบ
===============================================================================

 ฝั่งลูกค้า
  - ผังตลาดแบบ interactive: ซูม/เลื่อน, กรองตามโซน/สถานะ, ค้นหาเลขแผง
  - แถบเลือกวัน + รอบ (DayRoundBar) และปฏิทินรายเดือน (BookingCalendar)
  - สีของแผงเปลี่ยนตามสถานะของ "วัน/รอบที่เลือก" แบบ realtime
  - จองหลายวัน/หลายรอบในครั้งเดียว (เลือกเร็ว / เลือกเป็นช่วง) จำกัดสูงสุดตามตั้งค่า
  - กันแผงระหว่างรอโอนเงิน มีตัวนับถอยหลัง (ค่าเริ่มต้น 30 นาที) หมดเวลาแล้วแผงว่าง
  - แนบสลิป: บีบอัดรูปในเบราว์เซอร์ (JPG/PNG/WebP) + คำนวณ hash กันสลิปซ้ำ
  - หน้า "การจองของฉัน": แท็บ ต้องทำ/ที่จะถึง/ผ่านมาแล้ว/ปิดแล้ว, timeline,
    ส่งสลิปใหม่เมื่อถูกขอ, ยกเลิก, ขอยกเลิกพร้อมแนะนำยอดคืนตามนโยบาย
  - ใบเสร็จรับเงิน (เลขที่ R2569-000001 + จำนวนเงินตัวหนังสือไทย) พิมพ์/บันทึกได้
  - ศูนย์แจ้งเตือน (ผลตรวจสลิป ผังเปลี่ยน ฯลฯ)
  - ล็อกอินด้วย Email/Password และ Google, ลืมรหัสผ่าน, ขอเบอร์โทรครั้งแรก

 ฝั่งผู้ดูแล / เจ้าของ
  - Admin Builder: ลากวางแผง/วัตถุ (ทางเข้า ห้องน้ำ เวที ฯลฯ), เปลี่ยนขนาด/หมุน,
    snap กริด, ปุ่มลูกศรเลื่อน, Delete ลบ, แถบเครื่องมือ responsive
  - จัดการโซน (สี/ราคา), ตั้งค่าตลาด (ชื่อ ขนาดเมตร กริด)
  - ตั้งค่าการจอง: วันเปิดตลาด, รอบขาย (สูงสุด 6), เวลาปิดรับ, จำนวนวันจองล่วงหน้า,
    เวลากันแผง, เวลาส่งสลิปใหม่, นโยบายคืนเงิน
  - ตรวจสลิป: รายการรอตรวจ, ดูรูปสลิป (ซูม/ลาก), เตือนสลิปซ้ำ, อนุมัติ/ปฏิเสธ/ขอสลิปใหม่
  - ตัดสินคำขอยกเลิก, บันทึกการคืนเงิน (แนบสลิปคืนเงิน), ยกเลิกโดย admin
  - ลบการจองถาวร (ยืนยัน 2 ขั้น พิมพ์รหัสแผงยืนยัน + บันทึกเหตุผล)
  - Audit log: ค้นหา/กรองการกระทำทั้งหมด (owner ลบได้)
  - รายงานรายได้: รายวัน/เดือน, เทียบช่วงก่อนหน้า, อัตราการใช้แผง, ส่งออก .xlsx/.csv
  - จัดการสมาชิก, เปลี่ยนรหัสผ่านบังคับสำหรับบัญชี staff ใหม่

 7.1 จุดเริ่มต้น
-------------------------------------------------------------------------------
 src/main.js
   สร้างแอป Vue + Pinia และ mount ที่ #app โดย import('./App.vue') แบบ dynamic
   เพื่อดัก error ตอนเริ่ม (เช่น ไม่มีค่า Firebase) ถ้าเป็น production จะแสดงข้อความ
   "ระบบขัดข้อง" แบบเรียบ ๆ ไม่เปิดเผยชื่อ key ถ้าเป็น dev โยน error ให้เห็นเต็ม

 src/firebase.js
   อ่านค่า VITE_FIREBASE_* จาก .env, ตรวจว่าครบ (ไม่ครบ throw error),
   สร้าง app / db (Firestore) / auth, เปิด Analytics ถ้ารองรับ
   firebase/config.js แค่ re-export ไฟล์นี้

 src/App.vue  (ไฟล์ประสานงานหลัก)
   - ไม่ใช้ vue-router: สลับหน้าด้วย marketStore.activeMode
       'customer' → CustomerStallMap (ผังลูกค้า)
       'admin'    → StallCanvas (ผังแก้ไข)    [เฉพาะ admin/owner]
       'members'  → MembersPanel              [admin/owner]
       'slips'    → SlipReviewPanel           [admin/owner]
       'audit'    → AuditLogPanel             [admin/owner]
       'revenue'  → RevenuePanel              [owner เท่านั้น]
   - รวม modal ทั้งหมดไว้ที่นี่ (แก้แผง แก้วัตถุ โซน ตั้งค่าตลาด ตั้งค่าจอง จอง
     การจองของฉัน แจ้งเตือน เข้าสู่ระบบ โปรไฟล์ เปลี่ยนรหัสผ่าน)
   - onMounted: เริ่มฟัง auth, ฟังข้อมูลผังจาก Firestore, ฟังตั้งค่าตลาด,
     รับผลกลับจาก Google redirect
   - watch: ฟังแจ้งเตือน/การจองของฉันตาม uid, admin ฟังรายการรอตรวจสลิป,
     ถูกลดสิทธิ์/ออกจากระบบแล้วเด้งกลับหน้าลูกค้า
   - เตือนก่อนปิดแท็บถ้า admin มีผังที่ยังไม่บันทึก (beforeunload)
   - เปิดใบเสร็จเป็นหน้าเต็มผ่าน ?receipt=<bookingId>
   - บังคับเปลี่ยนรหัสผ่านถ้า mustChangePassword = true

 7.2 Stores (Pinia) : src/stores/
-------------------------------------------------------------------------------
 authStore.js  (ล็อกอิน/ผู้ใช้)
   state: currentUser, isAuthenticated, สถานะโหลด Google ฯลฯ
   getters: isAdmin, isOwner, needsPhone ...
   actions:
     initAuth()              ฟัง onAuthStateChanged (แหล่งความจริงเดียวของการล็อกอิน)
                             โหลดโปรไฟล์ role จาก users/{uid}
     register()              สมัครอีเมล/รหัสผ่าน
     login(loginId, pw)      ล็อกอินด้วยอีเมล หรือ username (แปลงด้วย loginId.js)
     loginWithGoogle()       popup ก่อน ถ้าถูกบล็อก fallback เป็น redirect
     completeRedirectSignIn()รับผลหลัง redirect
     ensureUserProfile()     สร้าง users/{uid} ครั้งแรกเท่านั้น role=tenant ไม่ทับของเดิม
     updateContactInfo()     บันทึกชื่อ/เบอร์โทร
     sendPasswordReset()     ส่งอีเมลรีเซ็ต (ข้อความเหมือนกันไม่ว่ามีบัญชีหรือไม่)
     changePassword()        reauthenticate แล้ว updatePassword
     logout()                ล้างแจ้งเตือนในเครื่องและข้อมูลฟอร์ม
     switchDemoRole()        สลับบทบาททดสอบ (เฉพาะ dev / VITE_DEMO_MODE=true)

 marketStore.js  (ผังตลาด ใหญ่ที่สุด ~1,000 บรรทัด)
   state: activeMode, theme (light/dark), ชื่อ/ขนาดตลาด (เมตร), scalePxPerMeter=40,
          zoom/pan, zones/stalls/layoutObjects (ฉบับ draft ของ admin),
          published (ฉบับที่ลูกค้าเห็น), selected*, ตัวกรอง, hasUnsavedChanges,
          initialStallsState/dirtyStallsMap (ติดตามว่าแผงไหนเปลี่ยน)
   actions:
     initFirebaseSync()      ฟังผังจาก Firestore แบบ realtime (ผ่าน keepAlive)
     addStall/updateStall/updateStallPosition/updateStallSize/removeStall
     addLayoutObject/update/rotate/position/size/remove  (วัตถุประกอบผัง)

โปรเจกต์นี้ไม่มี server เขียนเอง backend = Firebase ล้วน

 8.1 Authentication
   - Email/Password และ Google
   - ห้าม anonymous (rules ตรวจ sign_in_provider != 'anonymous')
   - บัญชี staff: ล็อกอินด้วย username → แปลงเป็นอีเมลภายใน

 8.2 Cloud Firestore
   - เก็บทุกอย่าง realtime ผ่าน onSnapshot (ครอบด้วย keepAlive ให้ฟื้นเอง)
   - ใช้ transaction/batch ทุกจุดที่เกี่ยวหลายเอกสาร

 8.3 Firestore Security Rules  (firestore.rules)  ** ส่วนสำคัญที่สุดของ backend **
   Rules ทำหน้าที่แทน server: เป็นผู้ตัดสินสิทธิ์และ "เครื่องสถานะ" ของการจอง
   ฟังก์ชันช่วย: isSignedIn, isNotAnonymous, userRole (อ่าน role จาก users/{uid}
   ไม่เชื่อค่าจาก client), isAdmin, isOwner
   กติกาต่อ collection:
     markets/{id}           อ่านสาธารณะ / แก้เฉพาะ admin / ตรวจ settings (รอบไม่เกิน 6)
     markets/{id}/stalls/*  ผู้เช่าเปลี่ยนได้แค่ available→pending ของตัวเอง
     bookings/{id}          อ่านเฉพาะเจ้าของ+admin; update ได้เฉพาะ "การเปลี่ยนสถานะ
                            ที่ถูกต้อง" (isValidDecision, isTenantCancel, isTenantPaySlip,
                            isExpireBooking, isAdminCancelDecision, isRefundRecord,
                            isReceiptIssue ฯลฯ) ห้ามแก้ยอด/ผู้เช่า/สลิป
     bookingLocks/{id}      lock กันจองซ้ำรายวัน/รอบ (id = stallId + slotKey)
     bookingSlips/{id}      รูปสลิป (แยกออกจาก booking ให้รายการเบา)
     auditLogs/{id}         สร้างได้ต่อเมื่อไปพร้อมการกระทำจริง (auditLinked) แก้ไม่ได้
     counters/receipts_YYYY เลขใบเสร็จ เพิ่มได้ทีละ 1 เท่านั้น ลบไม่ได้
     refundAccounts / refundSlips   บัญชีรับเงินคืน / สลิปคืนเงิน (แยกจาก booking)
     users/{uid}            อ่านของตัวเอง/admin; สร้างเป็น tenant เท่านั้น; แก้ role ไม่ได้
     notifications/{id}     อ่าน/ลบของตัวเอง; ผู้เช่าแก้ได้เฉพาะ isRead; admin สร้าง
   จุดที่ซับซ้อนที่สุด:
     - หมดเวลากันแผง: ไม่มี server จึงใช้ request.time เทียบ holdStartedAt+holdMinutes
       และบังคับ holdMinutes ให้ตรงกับตั้งค่าตลาด (กันผู้เช่าตั้งเวลายาวเอง)
     - ใช้ getAfter() ตรวจว่า booking กับสถานะแผง/lock เปลี่ยนไปพร้อมกัน
     - ลบการจองต้องมี audit log id ตายตัวไปพร้อมกัน (auditDeleteOk)

 10. ขั้นตอนการจอง และสถานะ
===============================================================================

 Flow หลัก
  1) ผู้เช่าล็อกอิน เลือกวัน/รอบ แล้วคลิกแผง
  2) BookingModal ตรวจกติกา (วันเปิด, เวลาปิดรับ, จำนวนสูงสุด) ที่ client
  3) bookStallSlots(): transaction สร้าง booking + lock ทุก slot (+สลิปถ้าแนบมาแล้ว)
     ถ้ามี slot ถูกจองก่อน → ล้มทั้งหมด ไม่มีข้อมูลค้าง
  4) ถ้ายังไม่แนบสลิป: สถานะ awaiting_slip กันแผงตามเวลา (ค่าเริ่มต้น 30 นาที)
     นับถอยหลังในหน้า "การจองของฉัน"; หมดเวลา → แผงว่าง (rules เป็นผู้ตัดสิน)
  5) แนบสลิป → pending → admin ตรวจ
  6) admin: approved (แผงเป็น booked + ออกเลขใบเสร็จ + แจ้งเตือน)
            rejected (ปล่อยแผง) หรือ needs_slip (ขอสลิปใหม่ภายในเวลาที่กำหนด)
  7) ภายหลัง: ผู้เช่าขอยกเลิก (cancel_requested) → admin approve/deny
     → cancelled + บันทึกคืนเงินตามนโยบาย

 สถานะของการจอง
   awaiting_slip → pending → approved → cancel_requested → cancelled
                      │         └──────────────(deny)──────┘ กลับ approved
                      ├→ needs_slip → pending (ส่งใหม่) / rejected / expired
                      ├→ rejected
                      └→ cancelled (ผู้เช่ายกเลิกก่อนอนุมัติ)
   expired = หมดเวลากันแผง/ส่งสลิป
   การจองเก่าที่ไม่มี status ถือเป็น approved

 ทุกการเปลี่ยนสถานะที่สำคัญเขียน audit log ใน transaction เดียวกัน

 11. ความปลอดภัย
===============================================================================
  - Rules อ่าน role จากฐานข้อมูล ไม่เชื่อ client; สมัครเองได้แค่ tenant
  - ไม่เก็บ key/ความลับใน git: .env อยู่ใน .gitignore มี .env.example แทน
  - ห้าม anonymous; ปุ่มสลับบทบาททดสอบปิดใน production (เว้นแต่ VITE_DEMO_MODE=true)
  - ข้อมูลส่วนบุคคลไม่อยู่ในเอกสารที่อ่านสาธารณะ
  - รูปสลิปแยกเอกสาร จำกัดขนาด/ชนิดไฟล์ทั้งฝั่ง client และ rules; ลบรูปที่อนุมัติแล้วเกิน 1 วัน
  - Audit log แก้ไม่ได้ ลบได้เฉพาะ owner
  - ป้องกันจองซ้ำด้วย lock + transaction; กันสลิปซ้ำด้วย hash
  - Build หยุดถ้าไม่มี config; production ไม่โชว์รายละเอียด error

 13. วิธีติดตั้ง รัน และ deploy
===============================================================================
  1. npm install
  2. คัดลอก .env.example เป็น .env แล้วใส่ค่า Firebase จาก Console
  3. npm run dev            (เปิดเครื่อง dev)
  4. npm run build         (สร้าง dist/ — หยุดถ้า .env ไม่ครบ)
  5. npm run deploy        (build + deploy hosting, rules, indexes)
     หรือ deploy:hosting / deploy:rules แยกกัน
  6. สร้างบัญชี owner/admin: npm run seed:staff (ตั้ง GOOGLE_APPLICATION_CREDENTIALS เป็นไฟล์ service account ก่อน)

 ตัวแปร .env
   VITE_FIREBASE_*          ค่าโปรเจกต์ Firebase
   VITE_DEMO_MODE           เปิดปุ่มสลับบทบาททดสอบ (ห้ามเปิดในระบบจริง)
   VITE_PROMPTPAY_NUMBER    เบอร์ PromptPay ที่โชว์ตอนจอง
   VITE_STAFF_EMAIL_DOMAIN  โดเมนอีเมลภายในของบัญชี staff

 หมายเหตุ: โฟลเดอร์นี้ "ไม่มีไฟล์ .env" (ข้อมูลลับ) ผู้รับต้องสร้างเองก่อนรัน

 14. ข้อจำกัด / สิ่งที่ควรพัฒนาต่อ
===============================================================================
  - สลิปเก็บเป็น data URL ใน Firestore (ใช้แผน Spark ฟรี) ถ้าอัปเกรด Blaze ควรย้ายไป
    Firebase Storage (slipStorage.js เตรียมจุดสลับไว้แล้ว)
  - ไม่มี server จึงตรวจ "ปฏิทินตลาด" (วันเปิด/เวลาปิดรับ) ที่ client เท่านั้น
    rules ตรวจไม่ได้ (ผู้ที่แก้ client สามารถข้ามได้) และสถานะ "หมดเวลา" ถูกตั้งเมื่อมี
    admin เปิดหน้าเว็บ (ความถูกต้องของแผงยังถูก rules ตัดสินเสมอ)
  - ยังไม่มีการชำระเงินอัตโนมัติ ใช้การโอน PromptPay + ตรวจสลิปด้วยคน
  - มีโค้ดชุดเก่าที่ไม่ได้ใช้แล้ว: src/router/, src/views/ (HomeView, LoginView),
    src/components/Navbar.vue ปัจจุบัน App.vue สลับหน้าด้วย activeMode ไม่ใช้ router
    (สามารถลบได้ภายหลัง)
  - bundle ขนาดใหญ่ (คำเตือน > 500 kB) ควรแยก chunk/lazy load เพิ่มเติม
  - ขนาดไฟล์บางไฟล์ใหญ่ (marketStore, firebaseService) ควรแยกเป็นโมดูลย่อย
  - รายการงานที่ค้างจากการ code review ดูใน docs/CODE_REVIEW.txt
