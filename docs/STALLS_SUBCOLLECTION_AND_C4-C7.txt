 1. โครงสร้างข้อมูลใหม่
-------------------------------------------------------------------------------
  markets/main-layout                 ชื่อ โซน วัตถุ ขนาด   -> อ่าน: ทุกคน / เขียน: owner,admin
  markets/main-layout/stalls/{id}     แผงค้ารายแผง
       อ่าน: ทุกคน
       สร้าง/ลบ/แก้ผัง/แก้สถานะ: owner,admin
       ผู้เช่า (ล็อกอินจริง): แก้ได้เฉพาะ available -> booked ในชื่อตัวเอง
         โดยเปลี่ยนได้แค่ status/bookedBy/updatedAt และ bookedBy มีแค่
         { tenantId (= uid ตัวเอง), bookedAt, bookingId }
  bookings/{id}                       ชื่อ/เบอร์โทร/สินค้าของผู้จอง
       อ่าน: เจ้าของรายการ + admin
       สร้าง: ต้องเป็นชื่อตัวเอง และแผงนั้นต้องถูกจองในชื่อตัวเอง (bookingId ตรงกัน)
              ในคำสั่งเขียนเดียวกัน (transaction) -> สร้างรายการจองปลอมไม่ได้
  ไม่ใช้ Cloud Function: ทุกอย่างบังคับด้วย firestore.rules + transaction ฝั่ง client

  ผลข้างเคียงที่ตั้งใจ (แก้ B9): เอกสารแผงอ่านได้สาธารณะ จึงไม่เก็บชื่อ/เบอร์โทรไว้ในนั้น
  หน้าแก้แผงของ admin ดึงรายละเอียดผู้จองจาก bookings ผ่าน bookingId

  collection stalls/{id} ระดับรากเดิม (ไม่เคยใช้) ถูกถอด rules ออก -> เขียนไม่ได้ทุกคน

 2. รายงาน C4-C7
-------------------------------------------------------------------------------
  C4 Admin บันทึกผังเขียนทับการจอง ........ ก่อนหน้านี้ "ยังไม่แก้" -> แก้แล้ว
     บันทึกเฉพาะแผงที่ admin เปลี่ยนจริง และเฉพาะฟิลด์ที่เปลี่ยน (buildStallWrites)
     status/bookedBy ไม่ถูกเขียนถ้า admin ไม่ได้แตะ จึงทับการจองใหม่ไม่ได้
     ตรวจด้วย unit test (tests/stallSync.test.mjs)

  C5 snapshot ทับงานที่ยังไม่ได้บันทึก .... ก่อนหน้านี้ "ยังไม่แก้" -> แก้แล้ว
     ถ้ามีงานค้าง (hasUnsavedChanges) จะรวมเฉพาะ "การจองใหม่" และแผงใหม่ของผู้อื่น
     (mergeRemoteStalls) ตำแหน่ง/ขนาด/สถานะที่ admin แก้ไว้ไม่ถูกทับ
     ข้อจำกัด: ระหว่างมีงานค้าง ชื่อผัง/โซน/วัตถุ/ขนาดจากผู้อื่นจะยังไม่ถูกนำมาใช้
     จนกว่าจะบันทึก (กันทับงานที่แก้ค้างไว้)

  C6 การจองเขียน zones/ชื่อผังทับ ......... ก่อนหน้านี้ "ยังไม่แก้" -> แก้แล้ว
     transaction จองแตะเฉพาะเอกสารแผงนั้นกับ bookings ไม่ส่ง zones/ชื่อผังอีก
     และ rules ไม่ให้ผู้เช่าแก้เอกสารผังเลย (มี test)

  C7 บันทึกล้มเหลวแต่ UI บอกสำเร็จ ......... ก่อนหน้านี้ "ยังไม่แก้" -> แก้แล้ว
     บันทึกล้มเหลว = แจ้ง error, คง hasUnsavedChanges, ไม่ส่งแจ้งเตือนผู้เช่า
     แจ้งเตือนผู้เช่าส่งหลังบันทึกสำเร็จเท่านั้น
     การจองใช้ transaction เดียวเขียนทั้งแผงและรายการจอง (เดิมเขียนรายการจอง
     แยกทีหลังและกลืน error)
     ข้อจำกัด: บันทึกผังที่มีแผงเกิน ~450 รายการจะแบ่ง batch ไม่ atomic ข้าม batch
     (เขียนแผงก่อน แล้วค่อยเขียนเอกสารผังเป็นขั้นสุดท้าย)

  แถมที่แก้ระหว่างนี้: เลิก fallback ผู้เช่า 'demo-tenant-001' / 'tenant-anon'
  ตอนจอง/ส่งแจ้งเตือน (ถ้าไม่ทราบผู้เช่าจะไม่จอง/ไม่แจ้งเตือน) — เกี่ยวกับ C3

 4. สิ่งที่คุณต้องทำเอง (ลำดับสำคัญ)
-------------------------------------------------------------------------------
  1) Deploy rules "ก่อน" hosting:   npm run deploy:rules   แล้วค่อย   npm run deploy:hosting
     (client ใหม่เขียน subcollection ซึ่งต้องใช้ rules ใหม่)
  2) หลัง deploy ให้ admin/owner เข้า Admin Builder แล้วกด "บันทึกผัง" 1 ครั้ง
     เพื่อย้ายแผงจาก array เดิมใน markets/main-layout เข้า subcollection
     (ระบบจะลบฟิลด์ stalls เดิมให้เอง) ก่อนหน้านั้นการจองของลูกค้าจะแจ้งว่า
     "ไม่พบข้อมูลแผง... ผู้ดูแลอาจยังไม่ได้บันทึกผัง"
     การจองเดิมที่ฝังอยู่ใน array จะถูกย้ายไปพร้อมกัน (ตัดชื่อ/เบอร์โทรออกจากเอกสารแผง;
     รายละเอียดเดิมยังอยู่ใน bookings ถ้ามี แต่รายการเก่าที่ไม่มี bookingId จะแสดงชื่อผู้จองเป็น "-")
  3) ทดสอบด้วยบัญชีจริง 3 แบบ: ผู้เช่าจองแผง, admin ย้ายแผง+บันทึก, admin เปิดแผงที่ถูกจอง
     (ต้องเห็นชื่อ/เบอร์ผู้จอง), เปิดผังจากเครื่องที่สอง ต้องเห็นสถานะตรงกัน
  4) ใช้ emulator ทดสอบเองได้: npm run test:rules (ต้องมี Java)
