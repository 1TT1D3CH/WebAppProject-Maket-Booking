# Deploy: 6 ระบบที่เพิ่ม (หมดเวลาจอง · ยกเลิก/คืนเงิน · จองตามวัน/รอบ · รายงาน+Excel · ประวัติ+ใบเสร็จ · audit log)

> ห้าม deploy แค่ rules หรือแค่ hosting — ต้อง deploy **ทั้งสามอย่างในคำสั่งเดียว** เพราะโค้ดหน้าเว็บกับ rules ต้องตรงกัน
> (บทเรียน 10 ต.ค.: rules กับโค้ดไม่ตรงกัน = ขึ้น "Missing or insufficient permissions")

## ก่อน deploy

1. **สำรอง rules ปัจจุบัน**: Firebase Console → Firestore → Rules → copy ทั้งหมดเก็บไว้ที่
   `docs/rules-deployed-<วันที่>.rules` (commit ได้ ไม่มีความลับ) และเทียบกับ `firestore.rules` ใน repo
2. **จด Hosting release ปัจจุบัน**: Console → Hosting → Release history (ไว้ย้อนกลับ)
3. รันให้ผ่านก่อน: `npm run build` · `npm run test:unit` · `npm run test:rules`

## คำสั่ง deploy (คำสั่งเดียว)

```
npm run build && firebase deploy --only firestore:rules,firestore:indexes,hosting
```

(สคริปต์ `npm run deploy` ทำสิ่งเดียวกัน)

## หลัง deploy

1. รอให้ index ใหม่เป็น **Enabled** ใน Console → Firestore → Indexes
   - `bookingLocks (stallId, date)` และ `(roundId, date)` — ใช้ในหน้าจองและการลบรอบ
   - รายงานรายได้ใช้ query ช่วงเดียวฟิลด์ (ไม่ต้องมี index เพิ่ม)
2. เข้าเป็น admin/owner → เมนู **ตั้งค่าการจอง** แล้วตั้งค่า:
   - วันเปิดขาย / รอบตลาด / จองล่วงหน้า / เวลาปิดรับ
   - **เวลากันแผงรอสลิป** (ค่าเริ่มต้น 30 นาที) และ **เวลาส่งสลิปใหม่** (24 ชม.)
   - **นโยบายยกเลิก**: คืนเต็มก่อนวันขาย 3 วัน, น้อยกว่านั้นคืน 50%, วันขายไม่คืน
   - **ข้อมูลบนใบเสร็จ**: ชื่อตลาด ที่อยู่ เบอร์โทร เลขผู้เสียภาษี (ไม่บังคับ) ขนาดกระดาษ A5/A4
3. ทดสอบด้วยบัญชีทดสอบ 1 รอบ แล้วยกเลิกทิ้ง:
   จองไม่แนบสลิป → นับถอยหลัง → แนบสลิป → admin อนุมัติ (ได้เลขใบเสร็จ) → เปิดใบเสร็จ →
   ขอยกเลิก → admin อนุมัติ → บันทึกคืนเงิน → owner ดูรายงานแล้วส่งออก Excel → ดู "บันทึกการทำงาน" ว่าครบทุกขั้น
4. บอกผู้ใช้ให้ **ล้าง cache / ปิดแล้วเปิดแอปใหม่** บน iPad/มือถือ (หน้าเว็บเก่าที่ค้างอยู่จะยังจองแบบเดิมได้ แต่ฟีเจอร์ใหม่ไม่ขึ้น)

## ความเข้ากันได้กับโค้ดเก่าที่ค้างใน cache

| โค้ดเก่าทำอะไร | ผล |
|---|---|
| จองแผงแบบเดิม (ไม่มีวัน) | ผ่านต่อได้ (rules ยังรองรับ legacy) |
| ส่งสลิปใหม่/ยกเลิก/อนุมัติ (ไม่มีใบเสร็จ) | ผ่านได้ เลขใบเสร็จไม่บังคับตอนอนุมัติ — admin ออกเลขภายหลังได้จากหน้าใบเสร็จ |
| จองรายวัน/รอบแบบแนบสลิปเลย | ผ่านได้ |
| ฟีเจอร์ใหม่ (กันแผง ขอยกเลิก ฯลฯ) | ไม่ขึ้นจนกว่าจะรีเฟรช |
| หน้าเว็บเก่าแสดงสถานะใหม่ (`awaiting_slip`, `cancel_requested`, `expired`) | อาจแสดงเป็นข้อความสถานะดิบ ไม่พัง |

## โควตา Spark (อ่าน 50,000 / เขียน 20,000 ต่อวัน)

ประมาณการต่อผู้ใช้หนึ่งคนที่เปิดแอป 1 ครั้ง (ผังแผงราว 50 แผง):

| กิจกรรม | อ่านโดยประมาณ |
|---|---|
| เปิดผัง (เอกสารตลาด + แผงทั้งหมด) | ~51 |
| ดูสถานะแผงของวันที่เลือก (bookingLocks ของวันนั้น) | ~30 ต่อวัน/รอบที่สลับดู (สลับ 3 ครั้ง ≈ 90) |
| เข้าสู่ระบบ: การจองของฉัน + แจ้งเตือน | ~20–60 |
| **รวมต่อผู้ใช้** | **~150–250 อ่าน** |

- 100 ผู้ใช้/วัน ≈ 15,000–25,000 อ่าน — **อยู่ในโควตา**
- 500 ผู้ใช้/วัน ≈ 75,000–125,000 อ่าน — **เกินโควตา 50,000** ถ้าเปิดแอปบ่อย ต้องอัปเกรด Blaze หรือลดการสลับวัน
  (onSnapshot อ่านเฉพาะเอกสารที่เปลี่ยนหลังจากโหลดครั้งแรก)
- admin: เปิดหน้าตรวจสลิป ≈ 100–500 อ่านต่อครั้ง (6 รายการฟัง) ; รายงานรายได้ 1 ครั้ง ≈ 100–4,500 อ่านขึ้นกับจำนวนการจองในช่วง (ปุ่มรีเฟรชอ่านใหม่ทั้งหมด)
- เขียน: การจอง 1 ครั้ง = booking + lock ตามจำนวนช่อง + log (+ สลิป) ≈ 3–10 เขียน ; เขียนไม่น่าถึง 20,000 ที่ 500 คน/วัน

## วิธีย้อนกลับ (ต้องย้อน **ทั้งสองอย่างพร้อมกัน**)

1. Console → Hosting → Release history → เลือก release เดิม → Rollback
2. Console → Firestore → Rules → เปิดเวอร์ชันที่สำรองไว้ → Publish
3. ข้อมูลรูปแบบใหม่ที่เขียนไปแล้วเมื่อเปิดด้วยโค้ดเก่า:
   - การจองรายวัน/รอบ (`slots`, `bookingLocks`) ใช้ได้ในโค้ดตั้งแต่ส่วน 2 ; ถ้าย้อนไปก่อนส่วน 2 จะเห็นเป็นรายการจองที่ไม่มีวันที่ และผังไม่รู้จัก lock
   - สถานะ `awaiting_slip` / `cancel_requested` / `expired` โค้ดเก่าแสดงเป็นข้อความดิบ ไม่ทำงานต่อ
   - ใบเสร็จ/คืนเงิน/ตัวนับ `counters` เป็นเอกสารแยก ไม่กระทบโค้ดเก่า

## ข้อจำกัดที่รู้อยู่แล้ว

- สถานะ "หมดเวลา" ถูกตั้งโดยหน้าเว็บของเจ้าของการจองหรือ admin ที่เปิดอยู่ ถ้าไม่มีใครเปิด แผงยัง **ว่างให้จองทับได้แล้ว** (rules ตัดสินด้วยเวลา server) เพียงแต่รายการเก่ายังเป็น "รอชำระเงิน" จนกว่าจะมีคนเปิด
- แจ้งเตือนในแอปส่งโดย admin เท่านั้น (rules `notifications` สร้างได้เฉพาะ admin) จึงไม่มีแจ้งเตือนถึง admin เมื่อผู้เช่าขอยกเลิก — ดูจากป้ายตัวเลขบนเมนู "ตรวจสลิป" แทน
- ปฏิทินตลาด (วันเปิด/ปิด จองล่วงหน้า เวลาปิดรับ) ตรวจที่หน้าเว็บเท่านั้น
- audit log กันการลบจากหน้าเว็บ/ผู้ใช้ทุกระดับ แต่ owner ที่เข้า Firebase Console ยังลบได้ (กันไม่ได้บน Spark)
- การยกเลิกหลายรายการพร้อมกันตามวัน (ตลาดปิดทั้งวัน) ยังไม่ได้ทำ ใช้ "ยกเลิกการจองนี้ (ผู้ดูแล)" ทีละรายการ
- ใบเสร็จบันทึกเป็น PDF ผ่านเมนูพิมพ์ของเครื่อง (ไม่มีปุ่มดาวน์โหลด PDF ทันที — ต้องเพิ่ม library + ฝังฟอนต์ไทย ถ้าต้องการให้บอก)
